# 变更摘要 2026-10-04

## check_hanzi_range.py（新增）—— 命令行判断字符串中汉字是否都在 3500/7000 范围内
- 用法: `python check_hanzi_range.py "字符串"` / `--text` / 管道传入; 支持 `--json` / `--detail`。
- 用 CJK 正则(基本区/扩展A/兼容/扩展B主区)提取汉字, 非汉字(字母/数字/标点/空格)不参与判定。
- 输出: 全部在3500内? 全部在7000内? 并列出「在3500内 / 在7000但不在3500(次常用) / 超出7000(集外)」三类汉字。
- 结合编码方案给出结论提示: 全3500→base62; 含3500外但在7000内→base85; 含集外→需3字符兜底。

## hanzi_z85.py（二次修订）—— 符合"3500→base62 / 超出→base85 / 同字可反查不依赖字符集"规格
- 重写为双模式 + 自描述前缀：全在 3500 内 → base62(前缀`6`)；超出 3500 → base85/Z85(前缀`8`)。
- 两张固定词表名次与字符集归属无关(全局一致)：`C3500`(3500字, base62, 2字符, 容量3844)、`C7000`(7000字, base85, 2字符, 容量7225)。
- 顶部 1 字符前缀自描述编码方式，解码`decode()`读前缀即选表，逐 2 字符反查汉字，**不需人工区分 3500/7000 字符集**。
- 同一汉字 -> 固定名次 -> 在各自模式下编码恒定一致；不同进制对同一名次渲染串必然不同(数学必然, 非 bug)。
- 超纲(不在7000词表)的汉字 `encode` 抛 `KeyError` 并提示码点。
- CLI：`encode/decode/info`，`--base 62|85|auto`(默认 auto 按是否在3500内自动选)、`--no-prefix`、`--in/--out`。

## hanzi_z85.py（初版）—— 汉字→Z85 定宽编码（方案锁定）
- 锁定方案：**词表上限 7000 字，一个汉字固定编码为 2 个 Z85 字符**（85²=7225 ≥ 7000，容量充足）。
- 重写 `HanziCodec`：加载词表 → 按 Unicode 码点升序去重 → 名次 k∈[0,N-1] → Z85(2字符)。
- 新增容量校验：词表字数超过 7225(2字符容量) 或假定上限 7000 时启动即报错。
- 新增超纲处理：`encode` 遇到词表外汉字抛 `KeyError`，提示该字码点，便于定位。
- 新增模块级便捷函数 `encode/decode/is_in_vocab` 与正式 CLI：`encode` / `decode` / `info` / `build-topn`。
- CLI 支持 `--charset` 指定词表、`--in/--out` 文件读写。

## data/hanzi_top7000_2025.json（新增）
- 由 2025 年 25 亿语料字频表 `...corpus ordered by frequency.csv` 取前 7000 高频字生成，
  作为比 1988 年 `hanzi_common_7000.json` 更贴合现代语料的备选词表。
- 实测两份词表交集 6210、各 790 独有。

## 重要结论（真实语料约束）
- 真实小说语料(`E:\Books\精校小说`)约需 12000 个不同汉字；7000 词表的 2 字符方案
  仅覆盖约 25% 的不同汉字（1988-7000 与 2025-7000 在古典小说样本里基本打平，1988 略优）。
- 因此：7000/2字符方案适用于"受限词表文本"；对任意中文全文编码需配套 3 字符兜底方案。
