# saferm 与 GNU rm 的兼容性报告

- 日期：2026-10-07
- 被评版本：saferm 1.0.0-dev（Linux amd64，`build/saferm-linux-amd64`）
- 对照对象：GNU coreutils 9.4 的 `rm`
- 测试环境：WSL 2（Ubuntu），内核 `6.18.40.1-microsoft-standard-WSL2`，非 root 用户 `mcxiaoke`，`/tmp` 为 ext4
- 复现方式：`make build-linux && wsl.exe -- bash -lc 'bash tests/compat-rm-vs-saferm.sh /tmp/compat.md'`

> **本报告对应的版本**：第一轮测量在 saferm 1.0.0-dev 上完成；之后按 §8 的建议实施了
> 三项改进（接受 `--preserve-root`、未识别参数报错时给出等价写法、README 增加迁移小节），
> 并顺带修掉 `saferm where` 的静默失败。**下面的数字与结论均已按改进后的二进制重新测量。**

> 结论先行：**31 个场景里 25 个退出码一致、26 个"原目录终态"一致。**  
> 剩余 9 处差异分两类：**4 处行为差异**（`-f` 配空变量、整批原子性、引号通配符、`-i` 非交互），  
> 以及 **4 个 rm 参数 saferm 不接受**（`-d`/`-I`/`--one-file-system`/`--no-preserve-root`）。  
> 其中 **`-f` 配空变量会从"静默成功"变成"退出 1"**、  
> **整批删除从一个不存在就"删掉其余"变成"一个都不动"** 这两条最需要注意；  
> 不接受的参数会**直接报错并给出等价写法**，而不是静默降级（`--preserve-root` 已改为接受并忽略）。

---

## 1. 测试方法

`tests/compat-rm-vs-saferm.sh` 对**同一份场景**跑两遍：一遍用 `rm`，一遍用 `saferm`，  
各自在全新的沙箱目录里，记录四件事：退出码、退出后沙箱里的实际内容、是否真的把东西搬进了回收区、  
以及两者的"终态"是否一致。

几个刻意的安排：

- 沙箱全部放在 `/tmp` 下的独立目录，**不在任何 Git 仓库内**：这样 31 个场景的差异都只来自
  "rm vs saferm"本身，不会被"目标是否位于版本库工作区内"这类语境干扰。
  （注：本报告测量之后，saferm 已把"位于工作区内"从危险级降为纯展示，见 §8；
  但沙箱保持在仓库外仍然是必要的——否则 `myrepo` 这类夹具本身含 `.git`，
  会被护栏第 8 条拒绝，测不到 rm 的对应行为。）
- `saferm` 一律加 `--trash-root $T/.trash`，把回收区限制在沙箱内，不污染真实回收目录。
- stdin 全部接到 `/dev/null`：这是脚本/CI 的真实处境（非交互）。
- "终态一致"独立于"退出码一致"统计。**两者不是一回事**：`rm` 可能"删掉一部分还返回 1"，  
  而 `saferm` 可能"整批预检不过但退出码同样是 1"——只看退出码会漏掉这种差异（见场景 18）。

## 2. 退出码语义对照

| 码 | `rm` 的含义                  | `saferm` 的含义             | 是否兼容                        |
| - | ------------------------- | ------------------------ | --------------------------- |
| 0 | 全部成功                      | 全部成功（目标已移入回收区）           | ✅ 兼容                        |
| 1 | 有任意一项失败（**其余成功的已经真的删掉了**） | 用法错误或护栏拒绝，**未发生任何移动**    | ⚠️ 数字相同，但"做了一半"与"什么都没做"是两回事 |
| 2 | 不使用                       | 部分失败（部分目标被占用/权限失败，其余已移动） | ➕ saferm 独有                 |
| 3 | 不使用                       | 用户在确认处取消                 | ➕ saferm 独有                 |

**对脚本的影响**

- `if cmd; then ...` / `$? -ne 0` 这类"成功与否"判断**依然成立**。
- 但任何"按具体退出码分支"的脚本需要复核：`saferm` 独占 2 和 3，  
  且 `1` 意味着**数据一个都没动**（可以安全重试），而 `rm` 的 `1` 意味着**已经动过了**（不能盲目重试）。

## 3. 参数支持对照

| `rm` 参数                   | `saferm` 行为                                        | 说明                                              |
| ------------------------- | -------------------------------------------------- | ----------------------------------------------- |
| `-f`, `--force`           | ✅ 支持，但语义**收窄**                                     | 只做两件事：① 路径不存在不报错；② 跳过**确认级**。不跳过危险级、不碰护栏        |
| `-r`, `-R`, `--recursive` | ✅ 接受但忽略                                            | 目录递归本来就是默认行为                                    |
| `-i`                      | ✅ 支持，但语义**强化**                                     | 强制确认（覆盖 `-y`/`-f`）。非交互环境下会**拒绝**而不是静默放弃         |
| `-v`, `--verbose`         | ✅ 支持                                               | 打印每个目标的详细处理过程                                   |
| `--`                      | ✅ 支持                                               | 用于 `-` 开头的文件名                                   |
| `-d`, `--dir`             | ❌ **不接受**                                          | 报用法错误。删目录请直接用路径（会走确认级，加 `-y` 跳过）                |
| `-I`                      | ❌ **不接受**                                          | 报用法错误                                           |
| `--one-file-system`       | ❌ **不接受**                                          | 报用法错误。saferm 的回收根判定本身就要求同卷，不会跨文件系统移动            |
| `--preserve-root` | ✅ **接受但忽略** | 卷根保护恒为开启、无法关闭，所以该参数对 saferm 恒为真，接受它零安全成本。`--preserve-root` 与 `--preserve-root=all` 两种写法都收 |
| `--no-preserve-root` | ❌ **明确拒绝** | 它要求关闭卷根保护，与本工具的存在意义冲突；报错时会说明原因 |
| `--interactive=WHEN`      | ❌ **不接受**                                          | 报用法错误                                           |
| 其它未列出的 rm 参数              | ❌ 不接受                                              | saferm 对未知开关一律报错，**绝不静默忽略**                     |
| —                         | ➕ `-n/--dry-run`                                   | rm 无对应物                                         |
| —                         | ➕ `-y/--yes`、`--yes-i-am-sure`、`--allow-dangerous` | 分级授权，rm 无对应物                                    |
| —                         | ➕ `--trash-root`、`--config`、`--literal`            | rm 无对应物                                         |

> **关键点**：`saferm` 不认识的参数会让命令**直接失败**（退出 1），报错里会说明 ① 是哪个参数、② 对已知 rm 参数给出**等价写法**，而不是"忽略它继续删"。
> 而不是"忽略它继续删"。这是有意的——静默忽略一个安全相关参数（尤其 `--no-preserve-root`）比失败危险得多。  
> 但代价是：任何用了上表 ❌ 参数的脚本，换成 saferm 后需要先改参数。

## 5. 六个必须知道的行为差异

### 5.1 `-f` 配空变量：从"静默成功"变成"退出 1" ⭐ 最重要

```
$ rm -f ""              → 退出 0（什么都没删，也不报错）
$ saferm -f ""          → 退出 1
  预检未通过，共 1 项，整批未执行（原数据未改动）
  - 参数是空字符串或纯空白。若要删除名为 $null 的文件，PowerShell 里请写 saferm '$null'（用单引号）
```

脚本里 `rm -f "$VAR"` 在 `VAR` 为空（或变量名拼错、未 `set -u`）时**曾经静默通过**，  
换成 saferm 后会**失败**。这正是本工具要拦的场景（背景事故就是 `"$null"` 展开成空串），  
所以这是**特性而非缺陷**——但它是迁移时最容易踩的一条：现存脚本必须改成先校验变量，  
或显式容忍这种失败。

### 5.2 整批原子性：一个不存在 → 全批不动

```
场景：saferm a.txt c-missing.txt
$ rm a.txt c-missing.txt      → 退出 1，a.txt 已经真的被删掉了（c-missing.txt 报错）
$ saferm a.txt c-missing.txt  → 退出 1，a.txt 仍在原地（整批预检失败，一个都没动）
```

`rm` 是"逐个尽力而为"，`saferm` 是"预检全过才动手"。对脚本的含义：  
**saferm 失败后重试是安全的**（数据没变），而 rm 失败后不能盲目重试。  
反过来，批量删除时若列表里混入了不存在的路径，saferm 会整批停下——要么先过滤，  
要么显式加 `-f`（`-f` 下不存在的项被静默跳过，其余照常移动）。

### 5.3 引号包住的通配符会被 saferm 自行展开

```
$ rm '$T/g*.log'      → 退出 1（把它当字面文件名，找不到）
$ saferm '$T/g*.log'  → 退出 0，g1.log 与 g2.log 都被移入回收区
```

这是为 PowerShell 做的折中（pwsh 不展开通配符，会把 `*.log` 原样传给程序）：  
**字面路径优先，字面不存在且含通配符时才由工具展开，展开为空则报错**。  
在 bash 里，如果你**故意**要删一个名叫 `a*b` 的文件，因为"字面优先"它仍然会当作字面路径处理；  
要彻底关掉展开用 `--literal`。

### 5.4 `-i`/`-I` 在非交互环境下：saferm 拒绝，rm 静默放弃

```
$ rm -i target.txt      → 退出 0，文件仍在（EOF 被当作"否"）
$ saferm -i target.txt  → 退出 1
  需要人工确认，但当前不是交互式终端。如确认无误，请显式加 --yes 或 -f
```

两者都**没有删数据**，但退出码不同。若脚本用 `rm -i` 并检查 `$?`，换成 saferm 后行为会变。  
`-I`（交互一次）saferm 完全不接受，会报用法错误。

### 5.5 未识别的 rm 参数直接失败，但会告诉你等价写法

`-d`、`-I`、`--one-file-system`、`--no-preserve-root` 都会得到**退出 1**，报错里有两层信息：

```
saferm: unknown shorthand flag: 'd' in -d
saferm: saferm 没有 -d（rm 用它只删空目录）：直接给目录路径即可，目录默认走确认级，加 -y 可跳过
用法：saferm [选项] <路径>...（saferm --help 查看全部选项）
```

第一行是 pflag 的原始错误。**此前这一行被整个吞掉了** —— 用户只看到一句用法提示，
根本不知道是哪个参数错了，这是个真 bug，本轮已修。第二行是针对已知 rm 参数的等价写法。

这比"静默忽略"安全（尤其 `--no-preserve-root`），代价是迁移时要逐个替换参数。
另外 `--interactive=WHEN` 稍特殊：saferm 定义了 `--interactive`（布尔，等价 `-i`），
所以 pflag 报的是"取值非法"而不是"未知参数"；等价写法提示同样会给出。

`--preserve-root` 是例外：它**已被接受并忽略**（saferm 的卷根保护恒为真），不再报错。


### 5.6 目录默认需要确认

`always_confirm_dir` 默认为 `true`，所以 **`rm -r dir` 在非交互脚本里不能直接换成 `saferm dir`**  
（会因需要确认而退出 1）。等价的写法是 `saferm -rf dir` 或 `saferm -ry dir`。

## 6. 脚本迁移清单

| 原来的写法                         | 建议改成                                    | 原因                              |
| ----------------------------- | --------------------------------------- | ------------------------------- |
| `rm -f "$LOG"`                | 先判空：`[ -n "$LOG" ] && saferm -f "$LOG"` | 空变量会让 saferm 退出 1（§5.1）         |
| `rm -rf "$DIR"`               | `saferm -rf "$DIR"`                     | 可直接替换                           |
| `rm -r "$DIR"`                | `saferm -rf "$DIR"`（或 `-ry`）            | 目录默认要确认（§5.6）                   |
| `rm dir1 dir2 ... `           | 先过滤存在性，或加 `-f`                          | 否则一个不存在就整批不动（§5.2）              |
| `rm -d "$EMPTYDIR"`           | `saferm -y "$EMPTYDIR"`                 | saferm 没有 `-d`（§5.5）            |
| `rm -I files...`              | `saferm -y files...`                    | `-I` 不被接受                       |
| `rm -i "$F"`                  | `saferm -iy "$F"` 或 `saferm -f "$F"`    | 非交互下 `-i` 会拒绝                   |
| `rm --preserve-root -rf "$D"` | `saferm --preserve-root -rf "$D"`（参数可保留） | 已接受并忽略，可直接替换 |
| `rm -rf --no-preserve-root /` | **不要迁移**                                | saferm 拒绝关闭卷根保护                 |
| 条目数超 `danger_file_threshold` 的大目录   | `saferm --yes-i-am-sure ...`            | 危险级只认这个开关，`-y` 无效               |
| 测试里删除临时文件                     | `saferm --trash-root "$TMP/trash" ...`  | 隔离回收区，避免污染真实回收目录                |

## 7. Agent 使用建议

给"由 agent/脚本自动调用 saferm"的几条具体规则：

1. **先 `-n` 干跑再动手**：`saferm -n <目标>` 只打印会移动到哪、有多少条目，零副作用，  
   且会执行全部护栏检查。agent 应当先跑一遍干跑并把结果呈现给人，再执行真删除。
2. **不要用"未校验变量 + `-f`"**。空串/纯空白 operand 在任何开关下都会失败（这是设计）。  
   agent 拼路径时要显式校验非空。
3. **按退出码区分处理**：
   - `0` 成功；
   - `1` 用法错误或护栏拒绝，**数据一个都没动**，可以安全修参数后重试；
   - `2` 部分失败，**已经有目标被移走**，不要整体重试，应逐项对账（用 `saferm where` 看未完成批次）；
   - `3` 用户取消，数据未动。
4. **非交互环境必须显式授权**：确认级要 `--yes`（或 `-f`），危险级要 `--yes-i-am-sure`。  
   危险级只有两个触发条件：**条目数超过 `danger_file_threshold`**，或**目标自身就是版本库根**
   （直接含 `.git`）。仅仅是"位于某个仓库内"**不会**让 `-y` 失效——那是常开信号，
   拿它分级会让 `-y` 在任何真实项目里都没用（设计文档 §14 D11）。
5. **批量删除前先收敛列表**：因为整批是原子的，列表里一个不存在会让整批停下。  
   agent 应先做存在性过滤，而不是无脑加 `-f`（`-f` 会同时跳过确认级提示）。
6. **要 rm 式严格语义时用 `--literal`**，避免引号包住的通配符被自行展开。
7. **在测试/沙箱里用 `--trash-root` 隔离**，否则会把测试文件搬进真实回收目录。
8. **别指望 saferm 能拦住 agent 自己拼出来的真 `rm -rf`**——它只保护"通过 saferm 发起的删除"。

## 8. 本轮已实施的改进

以下三项是**第一轮测量之后按本报告的建议实施**的；报告里的数字已是改进后的结果。

1. **接受 `--preserve-root` 作为 no-op**。saferm 的卷根保护恒为开启，该参数对它恒为真，
   接受它零安全成本。用自定义 flag 值实现，因此 `--preserve-root`、`--preserve-root=true`、
   `--preserve-root=all` 三种写法都能收（GNU 9.x 文档里就是 `--preserve-root[=all]`）。
   其中 `=all`（拒绝删除与父目录不同设备的参数）本来就是 saferm 的行为：挂载点会被当作卷根拒绝，
   且回收根必须与目标同卷。**效果**：场景 30 由"不一致"变为一致，整体从 24/31 提升到 25/31。
   `--no-preserve-root` **仍然拒绝** —— 它要求关闭保护，不能接受。
2. **未识别参数报错时给出等价写法**。之前 pflag 的原始错误在 `ContinueOnError` 模式下
   完全没被打印，用户只看到一句"用法：…"，**根本不知道哪个参数错了**。现在先打原始错误，
   再针对已知 rm 参数（`-d`/`-I`/`--interactive`/`--one-file-system`/`--no-preserve-root`）
   补一句等价写法。
3. **README 增加「从 rm 迁移」小节**，含三件必知事项与 before/after 对照表，并指向本报告。
4. **危险级触发条件收窄**（本轮新增，见 §9 之前的说明）：原先"位于版本库工作区内"就升危险级，
   现在只有**目标自身是版本库根**才升；"位于工作区内"降为纯展示（摘要里仍显示仓库路径）。
   这条**只放宽、不收紧**：对脚本是改善——仓库里删普通文件/目录时 `saferm -y` 又能用了，
   `--yes-i-am-sure` 重新变成"真正用于体量很大的目录"的开关，而不是日常通行证。
   31 个场景的测量结果不受影响（夹具本来就在仓库外），本报告的数字没有变化。

顺带修掉的两个缺陷（实现时发现，不是原建议项）：

- `saferm where <未知参数>` **静默失败**：退出 1 却零输出。已改为打印原因 + 用法。
- `where` 子命令没有共用 rm 兼容面，`where --preserve-root` 被当成未知参数；
  现已与主命令一致（`-r`/`-R`/`--preserve-root` 在所有子命令上都被接受并忽略）。

**仍建议考虑、但本轮没做：**

- 接受 `-d`（"只删空目录"）。**不建议**：那会让用户以为"非空目录不会被删"，
  而 saferm 会整棵移走，属于静默改变语义，与设计原则冲突。保持拒绝 + 等价写法提示已够用。
- 为 `-f` 下"整批里有个别路径不存在"在摘要里明确计数，方便 agent 判断是否需要修列表。


## 9. 未覆盖 / 局限

- **交互式 TTY 路径未实测**：`-i` 输入 `yes`、危险级手敲目标名这些需要真终端的场景，  
  在非 TTY 下无法复现。它们由 `src/` 里的 Go 测试用注入方式覆盖，  
  但**退出码 3（用户取消）在真实终端下的可达性本轮没有实测**。
- **退出码 2（部分失败）本轮没有构造出来**：需要"预检通过、但移动过程中某项失败"  
  （例如目标被其它进程独占）。建议后续补一条针对性用例。
- **只对照了 Linux/GNU coreutils 9.4**。Windows 上没有 GNU rm 可比；macOS/BSD 的 `rm`  
  语义不同（没有 `--preserve-root` 等），未测。
- **跨卷、网络盘、UNC 路径未测**：设计上这类情况直接拒绝（不做"复制+删除"降级），  
  与 rm 的差异不适用。
- 本报告只覆盖**参数与退出码**层面的兼容性，不含性能与并发行为。

## 附：原始数据

原始数据由脚本生成，属于**临时产物**，因此放在 `temp/` 下、**不纳入版本库**：

```bash
make build-linux
wsl.exe -- bash -lc 'bash tests/compat-rm-vs-saferm.sh /mnt/c/<项目路径>/temp/compat-table.md'
```

跑完得到两份文件：

- `temp/compat-table.md`：汇总表，31 行，含每条的完整命令、两边退出码、两边的沙箱终态、
  搬入回收区的条目数，以及「退出码一致 / 终态一致」两列。
- `temp/compat-table.detail.txt`：逐例的 stdout/stderr 原文（含 rm 的报错与 saferm 的中文提示），
  本报告 §5 的引文都取自这里。

沙箱留在 `/tmp/saferm-compat.<随机>` 供核对，确认后可自行删除。

> 说明：表中的沙箱路径带随机后缀，两次运行路径不同，这是正常的；
> 判断依据是「相对内容」而不是绝对路径。
