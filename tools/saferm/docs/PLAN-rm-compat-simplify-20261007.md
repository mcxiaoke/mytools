# 精简方案：定位切换为「trash 兜底、其余与 rm 一致」

- 日期：2026-10-07
- 状态：待实施（方案已确认方向，第 4 步含一处待拍板项）
- 前置阅读：[COMPAT-rm-vs-saferm-20261007.md](COMPAT-rm-vs-saferm-20261007.md)（31 场景实测报告）

---

## 1. 背景与定位变更

现行 saferm 的定位是「**拦截**是重点，移动只是手段」：12 条护栏 + 两级确认 +
整批原子，宁可拒错不可放过。代价是与 GNU rm 存在 9 处实测差异，无法直接替换
脚本里的 `rm`。

本方案将定位切换为「**trash 是重点，其余与 rm 保持一致**」：删除不可逆的风险
已由「只移动、不永久删除」这一本质消除，大部分护栏的 justification（防数据丢失）
随之消失，降级为「防打扰」可选项。目标是成为 **drop-in 的 safe better rm**：
脚本不改一行就能换，错了能反悔。

**改动原则：改动尽量小，不删任何模块。** `internal/guard`、`internal/trash`、
`internal/volume`、`internal/platform`、`internal/config`、不变量扫描全部保留，
改动集中在默认值、`rmcompat.go` 兼容层和 `app.go` 的预检结算方式。

## 2. 目标：清零兼容报告中的 9 处差异

对照实测报告，逐条对应：

| # | 差异 | 现状 | 目标 | 方案条目 |
|---|---|---|---|---|
| 1 | 场景 5：`-f` 配空参数 | 退出 1 | 静默成功（退出 0） | §5.3 |
| 2 | 场景 7：目录非交互需 `-y` | 需确认 | 不询问（退出 0） | §5.1 |
| 3 | 场景 16：自行展开通配符 | 展开且退出 0 | 与 rm 同：字面处理，不匹配即报错退出 1 | §5.3 |
| 4 | 场景 18：整批原子 | 一个不存在全不动 | 逐项处理，失败项报错、其余照常 | §5.3 |
| 5 | 场景 20：`-i` 非交互 | 硬拒绝退出 1 | EOF 按「否」跳过，退出 0 | §5.3 |
| 6 | 场景 9/28：`-d` 不接受 | 报用法错误 | 实现同 rm 语义 | §5.2 |
| 7 | 场景 27：`-I` 不接受 | 报用法错误 | 实现同 rm 语义 | §5.2 |

「原目录终态」是**移入回收区**而非真删——这是工具存在的意义，不算差异。

## 3. 设计前提

1. **不可逆风险已由 trash 消除**：任何目标的下场都是同卷 rename 进回收目录，
   全库无可永久删除的代码路径（不变量扫描继续保证）。护栏降级为可选项后，
   最坏后果是「麻烦」而不是「丢失」。
2. **rm 兼容优先于安全加码**：凡 rm 会做的，saferm 都照做（只是改成移动）；
   凡 rm 不问的，saferm 都不问。额外的保护只以「默认关闭的配置项」或
   「接受但忽略」的形式存在，绝不挡在正常脚本前面。
3. **正确性护栏不退场**：与「移动」这一动作本身正确性相关的检查保留——
   同卷校验、回收根互斥（第 9、10 条）、回收根标记校验、空参数/不存在路径的
   rm 同款报错。这些不是安全表演，是防止工具自己出错。

## 5. 分步实施

### 5.1 确认机制退位（改默认值，几乎零代码）

确认分级代码（`internal/ui`）不动，只改 `internal/config` 的内置默认值。
代码已支持「阈值为 0 = 不按此项判断」（见 `config.go` 的 `scanLimits`），
因此：

- `file_threshold`、`danger_file_threshold`、`bytes_threshold` 默认改为 0；
- `always_confirm_dir` 默认改为 false；
- `protect_vcs_root` 默认改为 false（rm 会删仓库；想拦截的人开配置即可）；
- `-y`、`--yes-i-am-sure`、`--allow-dangerous` 保留为「接受但基本无操作」，
  存量脚本零改动。

效果：平时**绝不询问**，只有 `-i`/`-I` 会问，与 rm 一致。

### 5.2 参数兼容层（`rmcompat.go`，纯增量）

- **`-d` / `--dir`**：实现。目录为空才移动；非空目录报
  `cannot remove 'x': Directory not empty`（退出 1），与 rm 文案对齐。
- **`-I`**：实现。operand 数 > 3 或含目录时确认一次；stdin 非终端读到 EOF
  按「否」处理（全部跳过则退出 0）。
- **`--interactive=never|once|always`**：映射为 默认 / `-I` / `-i`。
- **`--one-file-system`**：加入「接受但忽略」清单——saferm 本来只做同卷
  rename，此参数恒真（与 `--preserve-root` 同类）。
- **`--no-preserve-root`**：接受但忽略，卷根护栏仍在。saferm 永不永久删除，
  接受它零安全成本；`rm -rf /` 在两侧都失败（rm 靠缺参数，saferm 靠护栏）。
- 未知参数**继续报错**——这条本来就与 rm 一致，不动。

### 5.3 核心流程对齐 rm（`app.go`，方案中最大的一块）

1. **拆掉整批原子**（修场景 18）：预检从「一处拒绝全批不执行」改为 rm 风格的
   逐项处理——每个 operand 独立判定（`guard.Check` 逐项调用或按项收集），
   失败项打印 `saferm: cannot remove 'x': 原因` 后继续，其余照常移动；
   有任一失败最终退出 1。连带地，duplicate/nested 两条**批次级**规则在默认
   路径退场：父目录先移走后子项自然报「不存在」，行为恰好与 rm 相同
   （`rm a a` 第二次也是报「不存在」）。
2. **`-f` 配空参数静默成功**（修场景 5）：空 operand 在 `-f` 下按「路径不存在」
   跳过；不带 `-f` 仍报错退出 1（rm 同款文案）。
3. **去掉通配符自行展开**（修场景 16）：rm 从不展开 glob（shell 干这事）。
   `expandOperands` 改为恒等直通（函数保留备用），`--literal` 变成无操作
   开关保留兼容。字面通配符不匹配时报错退出 1，与 rm 一致。
4. **`-i` 非交互不再硬拒绝**（修场景 20）：`ui.Prompter` 在 stdin 非终端时
   仍然读提示，EOF 按「否」跳过该项；全部被跳过则退出 0、无移动。
5. **退出码对齐**：部分失败 2→1，取消 3→0（rm 的 `-i` 答「否」即跳过+退出 0）。
   `app.go` 内部常量保留，只改映射；`saferm where` 的非零语义不受影响。

### 5.4 保留为「超集能力」，不动代码

以下能力超出 rm，但都不挡正常脚本，全部保留：

- `-n`（dry-run）、`-v`、`--trash-root`、`--config`、`saferm where`；
- 清单 `.op.json`、操作目录镜像结构、回收根 `.saferm-trash-root` 标记校验；
- 同卷校验、回收根互斥护栏（guard 第 9、10 条）；
- 空参数/无参数/不存在路径的报错（rm 同款语义）；
- `.` 与 `..` 拒绝（rm 本身也拒绝，实测报告场景 22/23 已一致）；
- 配置文件 strict 解析、`internal/invariants` 不变量扫描。

**待拍板项（唯一）**：guard 第 5 条（cwd 祖先）与第 7 条（受保护系统目录）
是否保留默认生效。建议：**保留**——它们几乎不会挡住正常脚本，却是本工具
残余的「拦截」价值；若追求彻底的 rm 一致，可另挂 `guard.strict` 配置开关
默认关闭。实施时按「保留默认生效」处理，除非另有指示。

## 6. 验收标准

1. `make check`（gofmt + vet + test）与不变量扫描全绿；
2. 31 场景兼容对照：9 处差异清零，报告更新并注明「已按精简方案重测」；
3. 存量写法逐一验证：`rm -rf dir`、`rm -f "$VAR"`（含空值）、`rm a b c`
   （含不存在项）、`rm -d empty`、`rm -i f`（非交互）、`rm -I`（>3 项）
   均无需改参数直接替换 `rm`；
4. 「不会永久删除」的不变量不被本次改动破坏（扫描器约束的写操作白名单不变）。

## 7. 明确不做（本方案范围外）

- 不删除任何 guard 规则代码或配置键（只改默认值与默认路径）；
- 不实现跨卷「复制+校验」降级；
- 不引入自动清理 trash 的机制；
- 不改 trash 目录结构与清单格式。
