## 1. 背景与目标

**背景事故**：在 PowerShell 中清理一个名为 `$null` 的文件时（`$null` 在 pwsh 里是自动变量，`"$null"` 展开为空串），路径参数变成了空值，随后用 `rimraf` 清理，它把整个 Git 仓库删掉了，包括尚未 push 到远端的提交。

**这不是"手滑"，而是工具对空参数/危险路径缺乏拦截。** saferm 的设计重点因此是**拦截**，而不是"移动"本身——移动只是手段。

### 1.1 目标（v1）

| 编号 | 目标 |
|---|---|
| G1 | 删除 = 移动到指定目录，既不永久删除，也不进回收站 |
| G2 | trash 目录按文件所在磁盘自动选择，可用配置文件覆盖 |
| G3 | 一次删除涉及大量文件时，必须人工确认 |
| G4 | Windows 为主，同时支持 Linux（同一份代码交叉编译） |
| G5 | 单个可执行文件、零运行时依赖、无守护进程、无 GUI |

### 1.2 非目标（v1 明确不做）

- **不做 restore / undo**：手工在文件管理器里搬回去即可（见 §4.5），trash 布局已为此优化。
- **不做 `--permanent` 真正删除**：需要真正释放空间时，手工删除 trash 目录即可。工具本身不提供"绕过 trash"的通路。
- **不做跨卷复制降级**：见 §3.3。
- **不做回收站 API 集成**：行为不可控、Linux 无对应物。
- **不做自动过期清理**：trash 会持续占用磁盘，这是 v1 的已知取舍（见 §9）。
- **不做隐式通配符展开**：`*`、`?` 优先由 shell 展开。PowerShell 不展开通配符，因此采用"**字面路径优先**，字面不存在且含通配符时才由工具展开，**展开为空则报错**"的折中（见 §5.3 与 §14 D6）。
- **不做索引数据库 / 常驻服务**：每次调用的信息写在 §4 的清单文件里，不维护全局状态。
- **不是"安全擦除"**：`safe` 指"可恢复"，不是"不可恢复"。不做覆写、不做数据擦除。
- **不替换别的删除工具**：别名 / PATH 垫片只能降低手滑概率，**拦不住 `rimraf`、IDE、npm 脚本、AI agent 发起的删除**（见 §13）。这是明确的边界，不要当成防护。

## 2. 从事故中提取的硬约束

| 约束 | 说明 |
|---|---|
| C1 空参数必须硬失败 | 空串、纯空白、缺失的 operand 一律报错退出，且提示"要删名为 `$null` 的文件请写 `saferm '$null'`（单引号）" |
| C2 危险路径必须硬拦截 | 卷根、cwd 及其祖先、系统目录、VCS 仓库根（见 §5 完整清单） |
| C3 护栏不可被 `-f` / `-y` 绕过 | 否则脚本里一个 `-rf` 就把所有保护拆光，正是本次事故的模式 |
| C4 非交互环境默认拒绝 | stdin 不是 TTY 时，只要需要确认就直接拒绝。放行确认级要显式 `--yes` / `-f`，放行危险级要显式 `--yes-i-am-sure` |
| C5 失败不降级 | 任何一步失败就报错，绝不"顺手改成永久删除"或"跳过校验继续" |
| C6 不做隐式路径推导 | 路径不存在就报错，绝不猜测父目录、绝不把空路径当成 cwd |
| C7 失败即"没删" | 任何一步失败，原数据必须原封不动。输出要明说这一点，且**绝不因为失败而升级手段**（不"那我直接删吧"、不改属性重试、不降级为复制） |
| C8 代码里不存在永久删除 | v1 的代码路径里**不应该出现任何 `RemoveAll` / `DeleteFile` 调用**，全库审计一句话就能验证（见 §10.1） |

## 3. 核心机制：同卷 rename

### 3.1 为什么是 rename

同一文件系统内 `rename()` 是**纯元数据操作**：

- 不搬运数据，10GB 的 `node_modules` 也是瞬间完成；
- 原子，不存在"删了一半"的中间态；
- 保留 ACL、时间戳、属主、硬链接，无需额外备份；
- 反过来说，trash 里的文件**就是原文件本身**，不是副本。

### 3.2 实现方式

- Go 标准库 `os.Rename`。
- Windows：底层 `MoveFileExW`，同一卷内即元数据重命名。
- Linux：底层 `rename(2)`。
- **长路径不依赖系统设置**：自己把绝对路径转成 `\\?\` verbatim 形式后再调 API，而不是指望注册表的 `LongPathsEnabled`（本机虽已开启，但换台机器未必）。转换要把 `/` 统一成 `\`，并拒绝含 `..` 的相对路径。

### 3.3 跨卷的处理（已定：默认拒绝）

`os.Rename` 跨文件系统会失败（Windows `ERROR_NOT_SAME_DEVICE`，Linux `EXDEV`）。saferm **不做** `复制 + 校验 + 删原文件` 的降级：那是非原子的，进程中断会留下"两处都有 / 一处不完整"的状态，还要额外处理 ACL 与稀疏文件。

处理方式：

1. 移动前先判定目标与 trash 目录是否同一卷（Windows：`GetVolumePathNameW` 比较卷挂载点；Linux：`os.Stat` 比较 `st_dev`）。
2. 不同卷 → **报错退出**，并打印 `saferm where` 的建议配置，提示用户为该卷配置 trash 根。
3. 移动过程中收到 `EXDEV` → 同样报错退出（属于"判定与实际不一致"的异常，也要暴露出来）。
4. `--trash-root` 指定的目录若与目标不同卷 → 同样拒绝，不做例外。

## 4. trash 目录布局

### 4.1 布局

```
D:\.saferm-trash\                          # 每卷一个 trash 根
    20261006-143012-12345\                 # 操作目录（一次调用一个）
        projects\mytools\tools\saferm\     # ← D:\projects\mytools\tools\saferm 去盘符后的镜像
        temp\junk.txt                      # ← D:\temp\junk.txt
    20261006-143012-12345.op.json          # 本次调用的清单，与操作目录同级
    20261006-150203-18902\
        ...
```

**核心规则：去掉盘符/挂载点前缀，完整保留目录 tree。** `D:\a\b\c` → `<操作目录>\a\b\c`。

### 4.2 为什么外面套一层"操作目录"

| | 方案 A：操作目录（**采用**） | 方案 B：直接镜像到 trash 根 |
|---|---|---|
| 多次删除同一路径 | 天然不冲突，各自独立 | 必须给叶子加后缀，产生 `a`、`a~1`、`a~2`，**恢复时无法判断该搬哪个回去** |
| 恢复范围 | 一个操作 = 一个自洽快照 | 需要跨多次操作拼凑 |
| 审计 | 目录名即时间戳 + PID，旁边有清单文件 | 无 |
| 手工恢复 | 进入对应操作目录，内容整体搬回盘根 | 整个 trash 根一次性搬回盘根 |

方案 B 在"同一路径被删两次"时会产生歧义：trash 根里同时躺着 `a`、`a~1`、`a~2`，手工恢复时无法判断该把哪个搬回去。这与"trash 布局要服务于手工恢复"的目标直接冲突，因此选择方案 A。

> 备选：如果你更想要"trash 根 = 盘根的直接镜像"，可以改为方案 B，但需要接受同名冲突加后缀带来的歧义。**这一点请在评审时确认。**

### 4.3 命名规则

- 操作目录：`YYYYMMDD-HHMMSS-<pid>`（本地时间 + 进程号，避免并发实例撞名）。
- 清单文件：与操作目录同名 + `.op.json`，**放在操作目录外面**，保证操作目录内部只有待恢复的内容、没有任何杂质文件。
- 同一路径出现在同一卷的多个操作目录里是允许的（各自独立快照）。

### 4.4 边界情况

| 情况 | 处理 |
|---|---|
| 目标就在卷根，如 `D:\foo.txt` | → `<操作目录>\foo.txt` |
| UNC 路径 `\\nas\share\a\b` | 去掉 `\\nas\share` 前缀 → `<操作目录>\a\b`；trash 根本身也放该共享的根目录下 |
| 操作数分布在多个卷 | 每个卷各自建一个同名操作目录 + 清单，互不影响 |
| 文件名含尾随点/空格（Windows 合法但易踩坑） | 用 verbatim 路径处理，不做任何重命名 |
| 目标是符号链接 / junction | 只 rename 链接本身，**绝不跟随链接**（也就不会误删链接指向的真实目录） |
| Windows 保留名：`con`、`nul`、`aux`、`prn`、`com1`… | **保留原名**（tree 结构要靠原名），靠 `\\?\` 前缀绕过保留名解析；测试必须覆盖 |
| 目标名与操作目录名撞车 | 不可能：镜像 tree 的第一层来自真实路径（如 `projects`），操作目录名是纯时间戳数字 |
| 同一操作目录内两个 operand 撞车 | 不可能：重复 operand 与祖孙 operand 已在 §5.1 拦截，其余路径的镜像位置必然互不相同 |
| 镜像路径仍然超长（超 32767） | 报错退出。**绝不为了塞进去而截断或改名**——那会破坏 tree 结构，也就破坏了手工恢复的前提 |

### 4.5 手工恢复步骤（写进 `--help`）

以"误删 `D:\projects\mytools\tools\saferm`"为例：

```
1. 打开 D:\.saferm-trash\，找到对应的操作目录（按时间戳）
2. 目录内部就是去盘符后的镜像：projects\mytools\tools\saferm
3. 把操作目录里的内容（projects 等）整体复制或移动到 D:\ 根目录
4. 覆盖确认对话框选择"替换"即可，结构天然对齐，不需要手工建目录
5. 可选：删掉该操作目录与对应的 .op.json
```

### 4.6 清单文件内容（最小化）

每个操作一个 JSON，不是索引库，只是"这次调用干了什么"的留痕：

```
time / host / user / cwd / 完整命令行
每个卷：trash 根、操作目录名
operands：原始参数 → 解析后的绝对路径 → 移动后的路径 → 结果（pending / done / skipped / failed）+ 文件数 + 总字节
```

### 4.7 回收根的身份标记与自我保护

回收根目录下必须有一个标记文件 `.saferm-trash-root`，内容含工具版本与创建时间。

规则：

1. 目录不存在 → 创建，并写入标记。
2. 目录存在且**为空** → 视为可认领，写入标记后使用。
3. 目录存在且有标记 → 正常使用。
4. **目录存在、无标记、且非空 → 拒绝使用并报错**。这是专门防配置笔误的：如果谁把 `roots.D` 写成 `D:\` 或某个已有数据目录，工具会在动手之前就停下来，而不是把文件镜像进一个真实目录、把里面搅乱。
5. 目标路径位于回收根之内、或是回收根的祖先 → 拒绝（见 §5.1 第 9、10 条）。
6. Windows 上给回收根设置**隐藏属性**，并在 README 提示把该目录加入索引/同步软件的排除列表（Everything、OneDrive 等），否则它会被反复扫描甚至上传。

将来如果增加 `purge`，它**只承认带标记的目录**，且必须校验目标路径规范化后确实位于带标记的回收根之下。v1 没有 `purge`，但这条约束先写死，避免以后加的时候把工具做成危险品。

## 5. 路径护栏（工具的核心价值）

### 5.0 路径规范化（所有检查的地基）

顺序固定，任何一步失败都按"拒绝"处理，不降级成"用未规范化的路径继续"：

1. **字符串层**：`filepath.Abs` + `filepath.Clean`；统一分隔符；Windows 上剥掉尾随的点与空格；比较时大小写折叠。
2. **Windows 短名展开（8.3 名）**：`D:\PROGRA~1` 与 `D:\Program Files` 字面比较并不相等，**只做字符串比较会让护栏和"cwd 祖先"判定被短名绕过**。必须调用 `GetLongPathNameW` 把每一段展开成磁盘上的真名。短名不是 reparse point，展开它**不违反**"不解析最后一级链接"的语义。API 调用失败（短名被禁用 / 路径不存在）→ 保守处理：拒绝并提示，不猜。
3. **不解析最后一级 reparse point**：保证"删链接本身而不是链接目标"。因此**不使用** `GetFinalPathNameByHandle` 这类"最终路径"API——它会解析 reparse point，与本工具的语义冲突。
4. 比较时 Windows 大小写不敏感、`/` 与 `\` 等价；Linux 按字节比较、大小写敏感。

### 5.1 硬拦截清单

**全部检查必须作用于"最终目标集合"**，而不只是命令行原始参数：通配符展开出的每一条路径，都要**重新完整走一遍本表**。

| # | 情况 | 行为 |
|---|---|---|
| 1 | operand 为空串 / 纯空白 | 报错退出 + 引号提示 |
| 2 | **一个 operand 都没给**（`saferm` 裸执行） | 打印用法 + 退出码 1。**绝不"没有参数就静默成功"** |
| 3 | 路径不存在 | 报错退出，不猜测。**只有显式带 `-f` 时才静默跳过该项**（rm 兼容语义） |
| 4 | 解析后 == cwd | 拒绝（`saferm .` 也会命中这条） |
| 5 | 解析后是 cwd 的**祖先** | 拒绝。`cwd=D:\repo` 时删 `D:\repo` 或 `D:\` 都会命中，正是本次事故的形态 |
| 6 | 卷根：`C:\`、`/`、`\\server\share` | 拒绝 |
| 7 | 系统关键路径：`%SystemRoot%`、`%ProgramFiles%`(`x86`)、`%ProgramData%`、`%USERPROFILE%` 本身；Windows 盘根下的系统目录（`$Recycle.Bin`、`System Volume Information`、`Recovery`、`Windows`）；Linux 的 `/etc` `/usr` `/bin` `/sbin` `/boot` `/var` `/lib` 等 | 拒绝 |
| 8 | 目录含 `.git` / `.hg` / `.svn`（VCS 仓库根），或就是 `.git` 本身。**`--worktree` 与 submodule 的 `.git` 是普通文件（内容为 `gitdir: ...`）而不是目录，两种形态都要识别** | 拒绝 |
| 9 | 目标位于任一 trash 根之内 | 拒绝（防止把 trash 再删进 trash） |
| 10 | **目标是任一 trash 根的祖先**（即某个 trash 根位于目标目录内部） | 拒绝。否则会把 trash 搬进它自己内部，必然失败或产生自引用 |
| 11 | 同一批 operand 中有重复项（按规范化后的路径判重） | 拒绝并列出重复项 |
| 12 | 同一批 operand 中存在祖孙关系（`saferm D:\a D:\a\b`） | 拒绝。移动 `D:\a` 时 `D:\a\b` 已经跟着走了，第二项会变成"路径不存在"，属于调用方搞错了意图 |

### 5.2 绕过与批次语义

- 只有 `--allow-dangerous` 能绕过上表的**危险路径类**拦截（第 4~10 条）。
- **参数错误类**（第 1、2、3、11、12 条：空参数、缺参数、路径不存在、重复项、祖孙关系）**任何开关都不能绕过**——这些是调用方写错了，只能改命令。
- 使用 `--allow-dangerous` 时仍然会显示**解析后的绝对路径**并要求确认。
- **`--allow-dangerous` 与 `--yes-i-am-sure` 同时出现时**，输出必须额外打印一行显著警告（例如"护栏与危险级确认均已关闭，本次操作可能不可逆"）。两个长开关叠加理论上已经能对卷根动手了，靠"要打两个长名字"当门槛够用；**但不要做成需要环境变量解锁**——把逃生门锁死只会逼人去用真 `rm`，那更糟。
- `-f` / `-y` **只**跳过 §6 的确认级提示，**不碰**上面任何一条。

**批次语义：预检失败 → 整批不执行。** 全部 operand 的路径解析、护栏检查、trash 根可用性、同卷判定都做完并通过之后，才开始移动。任何一项预检失败就整批退出（码 1），不做"删了一部分才发现配置不对"。

> 为什么保留逃生门：确实存在合法场景（例如在父目录里删掉自己所在的目录树）。但必须显式打出来，绝不能"顺手加个 `-f`"就生效。

### 5.3 已知局限（明确写出来，不假装完备）

- **无法防御 shell 自己的展开**：`rm -rf $DIR/*` 在 `$DIR` 为空时会变成 `rm -rf /*`，这是 shell 行为，任何工具都拦不住。saferm 能做的是"收到 `/*` 就拒绝"。
- **PowerShell 不做通配符展开**：pwsh 会把字面量 `*.log` 原样传给程序（bash 则会展开）。因此规则是**字面路径优先**：参数作为字面路径存在就按字面处理（`$null`、`[abc]`、`a*b` 这类怪名字文件因此能直接删）；字面不存在且含通配符时，才由工具自己展开并展示结果；**展开结果为空必须报错**，绝不"空模式匹配成当前目录"——那正是本次事故的形态。
- **展开结果是"新目标"，不是"参数的注解"**：展开出的每一条路径都要重新做完整规范化（§5.0）并完整走一遍 §5.1，逐个检查、逐个报错。绝不能只在参数层做一次检查就放行——`saferm *` 展开出的集合里如果混入 cwd 或 `.git` 仓库根，必须按护栏拒绝。
- 以 `-` 开头的文件名要用 `--` 分隔：`saferm -- -weird-name`。
- 护栏基于**字面绝对路径**比较。如果父链上存在 junction / symlink 指向别处，字面比较可能被绕过（例如 `D:\link` → `D:\`）。判断"是否为 cwd 祖先"时只比字面路径，不追链接——追链接会带来新的语义混乱。
- 不做 TOCTOU 级别的防护（检查与 rename 之间路径被换掉），这不是本工具要解决的问题。

## 6. 确认策略（G3：大量文件需人工确认）

### 6.1 流程

1. **扫描统计**：文件数、总字节、是否含子目录。**早退计数**——达到阈值立即停止遍历，避免在 `node_modules` 上卡住。
2. 扫描**不跟随符号链接 / junction**，只把链接本身计为 1 个条目。
3. **扫描失败按最坏情况处理**：遇到无权限目录、IO 错误、遍历中断导致统计不完整时，一律**强制要求确认**并在提示里标出"统计不完整"。绝不能因为"数不出来"就当成"没几个文件"而静默放行。
4. **两级确认**（任一条件命中即取更高级别）：
   - **确认级**：文件数 > `file_threshold`（默认 50）；或总大小 > `bytes_threshold`（默认 1 GiB）；或目标是目录（`always_confirm_dir = true`，默认开）；或统计不完整。→ 输入 `yes` 放行，`-y` 可跳过。
   - **危险级**：文件数 > `danger_file_threshold`（默认 5000）；或目标位于 VCS 工作区内（Git 基础档检测，见下）。→ **必须手敲目标的名字**（目录名/文件名，不含路径），`-y` 无效，`--yes` 也无效，`--yes-i-am-sure` 才能跳过，只有交互输入正确才继续。
     > 刻意**不把"目标在 cwd 之外"当危险级条件**：从固定目录启动时删任何别的路径都要手敲名字，太吵，结局是用户养成无脑加 `--yes-i-am-sure` 的习惯，危险级就形同虚设。危险级只由"体量"和"Git 工作区"这类客观高风险信号触发。
5. **Git 基础档检测（默认开，成本近零）**：从目标路径逐级向上查找 `.git`——**目录形态与文件形态（worktree / submodule 的 `gitdir:` 文件）都要识别**，命中则把风险级别提到危险级，并打印仓库根路径与"该目录在仓库内"。**只做展示，不调用任何 git 写操作**（绝不做 `reset`/`clean`/`restore`）。增强档（调用 `git status` 显示未提交/未推送数量，可选择性开启，默认关，命令不可用或超时 2 秒即跳过）留待后续，见 §14 D7。
6. 提示内容（一次调用汇总一次，不逐个 operand 打断；跨卷时**按卷分组**展示）：
   ```
   将移动到 trash：
     目标     D:\projects\mytools\tools\saferm   （解析后的绝对路径）
     内容     12,483 个文件 / 2.1 GiB / 含子目录
     仓库     D:\projects\mytools（Git 工作区内）
     目的     D:\.saferm-trash\20261006-143012-12345\projects\mytools\tools\saferm
     条目     前 5 条：...（完整清单用 -n 查看）
   危险级操作，请输入目标名称 saferm 以确认：
   ```
7. 输入校验严格匹配（`yes` 大小写不敏感；危险级按规范化后的名字精确比较），其它输入（含回车）一律取消，退出码 3。
8. `--dry-run` 只打印统计与目标位置，**不要求确认**（本来就不落盘）。

### 6.2 非交互环境

stdin 不是 TTY（管道、CI、计划任务、被其它脚本调用）时，**需要确认就直接拒绝**，报错提示"需要确认但当前非交互"，并指明对应的放行开关：

- 确认级 → 显式加 `--yes` 或 `-f`。
- 危险级 → 只能加 `--yes-i-am-sure`（名字故意写长，避免顺手打出来）。

这条直接封死本次事故的另一半成因：脚本里变量为空时静默执行。

## 7. 配置文件

### 7.1 位置与优先级

优先级从高到低：命令行参数 → 配置文件 → 内置默认值。

- Windows：`%APPDATA%\saferm\config.toml`
- Linux：`$XDG_CONFIG_HOME/saferm/config.toml`，回退 `~/.config/saferm/config.toml`
- 可用 `--config <file>` 指定；文件**不存在**时用默认值，不报错。
- 文件**存在但解析失败**（语法错误、类型不符）→ **报错退出，绝不静默回退默认值**。否则用户以为护栏生效了、其实配置根本没读进去，属于最危险的失败模式。报错要带行号与原文片段。
- **键名写错（拼写错误、不属于任何已知配置项）同样必须报错**，按 strict 模式处理。它与"静默回退默认值"是同一个失败模式的两种形态：护栏的实际取值与用户的预期不一致，而工具看起来一切正常。
- `--config` 指定的文件不存在 → 报错退出（用户是显式指定的，不能装作没看见）。

不做项目级配置（如向上查找 `.saferm.toml`），避免"在哪个目录执行行为就不同"这类难以察觉的差异。

### 7.2 格式与样例

配置用**标准 TOML**，交给成熟库解析（见 §10.1），不再自研子集——包括点号键、带引号的键在内的标准语法都可用。代价可忽略，换来的是"解析器本身不出错"和更准确的报错定位。

配置项刻意保持少：只有下表这几项，其余全部内置。

```toml
# saferm 配置

[trash]
# auto = 使用目标所在卷的 <卷根>\.saferm-trash
default_root = "auto"

# 按卷覆盖；键为卷标识：Windows 用盘符字母，Linux 用挂载点路径
[trash.roots]
C = "C:\Users\me\AppData\Local\saferm\trash\C"
D = "D:\.saferm-trash"
"/home" = "/data/.saferm-trash"

[confirm]
file_threshold       = 50            # 超过此文件数需要确认
danger_file_threshold = 5000         # 超过此文件数升为危险级（手敲名字）
bytes_threshold      = 1073741824    # 字节数，1 GiB
always_confirm_dir   = true          # 删目录一律确认

[guard]
protect_vcs_root = true     # 目录含 .git/.hg/.svn 时拒绝
git_detect       = true     # Git 基础档：目标在仓库内时升为危险级（.git 目录或文件都算；只提示，不调用 git 写操作）
extra_protected  = []       # 额外保护的绝对路径（Linux 上用 "/"、Windows 上用 "C:\..."）
```

### 7.3 trash 根的解析顺序

1. 配置里 `[trash.roots]` 有该卷 → 用它。
2. 否则用 `<卷根>\.saferm-trash`（**所有卷统一规则，包括 C:，不做特殊照顾**）。
3. 若该目录无法创建/不可写 → 尝试同卷的兜底候选，**必须校验与目标同一设备**，不同设备则拒绝：
   - Windows：`%LOCALAPPDATA%\saferm\trash\<卷>`
   - Linux：`$XDG_DATA_HOME/saferm/trash/<dev>`（`$HOME/.local/share/saferm/trash/<dev>`）
4. 全部不可用 → 报错退出，打印 `saferm where` 输出与建议配置。

> 统一用卷根，是为了让"trash 根 = 该盘内容的去盘符镜像"这个心智模型在所有盘上都成立；C: 根目录不可写时用兜底候选（此时兜底目录也在 C: 上，仍是同卷 rename）。

### 7.4 回收根的安全校验（§4.7 的落实）

解析出回收根后，动手之前必须依次通过：

1. 规范化路径，确认它不是卷根、不是已存在的非空陌生目录（无标记见 §4.7）。
2. 确认它与被删目标同卷（§3.3）。
3. 确认回收根与目标不是互为祖先的关系（§5.1 第 9、10 条）——**注意这一步要针对"最终解析出的回收根"做，不能只针对配置里的原始字符串**，否则 `roots.D = "D:\projects\trash"` + `saferm D:\projects` 这类配置能绕过去。
4. 通过后才创建目录、写标记、写清单。

## 8. 命令行接口

### 8.1 v1 命令面（刻意保持极小）

```
saferm [options] <path>...     移动一个或多个路径到 trash（默认行为）
saferm where                   打印生效配置、各卷解析出的 trash 根与可写性
```

Merge 掉 `doctor`：`where` 顺带完成"各卷可否写入 / 是否同卷 / 回收根有没有标记 / 有没有未完成的批次"的自检，不多加一条命令。`where` 正常退出码 0，检测到问题（某卷 trash 不可用、跨卷、未完成批次等）退出码 1，便于脚本判断。它**只读不写**（不创建 trash 目录）。

不提供 `list`：操作目录名是时间戳、旁边有清单文件，`ls` trash 根已经足够。

### 8.2 参数

| 参数 | 说明 |
|---|---|
| `-n`, `--dry-run` | 只打印将移动到何处与统计，**不创建任何目录/文件**；仍然执行全部护栏检查 |
| `-y`, `--yes` | 跳过**确认级**提示。护栏与**危险级**照旧生效 |
| `--yes-i-am-sure` | 唯一能跳过**危险级**的开关（名字故意写长）；非交互环境下要处理危险级必须用它。**不碰任何护栏** |
| `-f`, `--force` | 与 rm 的 `-f` 语义对齐，两件事：① 路径不存在不报错（跳过该项，退出码不受影响）；② 跳过**确认级**提示。**不跳过危险级，不碰护栏** |
| `-r`, `-R` | 接受但忽略：目录递归本来就是默认行为 |
| `-v`, `--verbose` | 打印每个 operand 的详细处理过程 |
| `--allow-dangerous` | 绕过 §5.1 的危险路径护栏，需显式打出。与 `--yes-i-am-sure` 同时出现时必须额外打印一行显著警告 |
| `--config <file>` | 指定配置文件 |
| `--trash-root <dir>` | 覆盖 trash 根（单次生效） |
| `--` | 选项结束符，用于处理以 `-` 开头的文件名 |
| `-h`, `--help` / `-V`, `--version` | |

可选兼容（成本低，对 pwsh 用户友好）：接受 `-Recurse`、`-Force`、`-LiteralPath` 作为上面的别名。

**`-r`/`-f` 的存在是为了让 `alias rm=saferm` 在多数场景下不掉链子，但 `-rf` 拆不掉任何护栏，也拆不掉危险级确认。**

`-f` 里的"路径不存在不报错"是必要的 rm 兼容项：Makefile / 脚本里 `rm -f build/x` 很常见，如果一律报错会逼着人换回真 `rm`。注意它与护栏第 3 条的关系——**默认（不带 `-f`）路径不存在要报错**，带 `-f` 才静默跳过。

### 8.3 退出码

| 码 | 含义 |
|---|---|
| 0 | 全部成功 |
| 1 | 用法错误或护栏拒绝（未发生任何移动） |
| 2 | 部分失败（部分 operand 因占用/权限失败，其余已移动） |
| 3 | 用户在确认处取消 |

### 8.4 输出规范

- 人类可读输出到 stderr（成功摘要也可到 stdout，便于管道），日志行用英文（遵循项目约定：标识符、日志、commit message 用英文，交互文案用中文）。
- 干跑输出到 stdout，格式稳定，便于人肉核对。
- **不写全局日志文件**：清单文件（§4.6）就是留痕，避免再维护一套日志轮转。
- **Windows 控制台编码**：启动时把控制台输出代码页设为 UTF-8（`SetConsoleOutputCP(65001)`），否则中文提示与含中文的路径在旧版 conhost 里会乱码；路径本身一律走宽字符 API，不走本地代码页。
- **失败时的措辞是硬要求**：任何失败都必须明确输出"原数据未改动"，不能只给一个错误码（C7）。

## 9. 失败处理与一致性

**贯穿全文的失败不变量（C7）：失败意味着"没删"。** 任何一步不成功，原数据都必须原封不动，且输出里要明确写出这一点。绝不允许"为了成功"而升级手段——不退回真删除、不自动改属性后重试、不降级成复制、不跳过校验。

清单里的条目状态机：`pending` → `in-progress` → `done` / `skipped` / `failed`（`skipped` 用于 `-f` 下路径不存在的情形）；整批汇总状态为 `done` / `partial` / `failed`。判断"某条目到底搬走没有"只以清单 + 回收区实物对账为准。

| 场景 | 处理 |
|---|---|
| 清单文件写不进去（权限/磁盘满） | **拒绝执行**，不移动任何东西。审计链不能断——移动了却没有留痕，等于把"可人工恢复"的前提丢掉了 |
| 某个 operand 被其它进程独占（Windows） | 记录失败原因，**继续处理其余 operand**，最后汇总，退出码 2 |
| 目录内有文件被占用导致整目录 rename 失败 | 报错，**不逐个文件降级处理**（那会破坏 tree 结构与原子性） |
| 只读属性的文件/目录 | rename 通常可行；若失败则报错，**不自动清除只读属性** |
| 已成功的部分是否需要回滚 | **不回滚**。回滚本身又是一次移动，二次操作只会放大风险；失败项在摘要里明确列出，人工处理 |
| 磁盘满 | 同卷 rename 不占额外空间，不受影响。但 trash 会持续占用空间（v1 已知取舍） |
| 中途被 Ctrl-C / 进程被杀 | 清单先写 `pending` 的完整计划，每完成一项就更新为 `done`/`failed`；任何时刻中断，都能看出"哪些已搬走、哪些没动"（`saferm where` 会把这些未完成的批次报出来，见 §8.1）。不做自动回滚 |
| 回收根存在但无标记且非空 | 拒绝使用并报错，提示检查配置（§4.7） |
| 并发多个 saferm 实例 | 操作目录名含 PID，天然不冲突；trash 根用 `MkdirAll` 幂等创建 |
| 权限 | Linux 上 trash 根创建后置 `0700`（trash 里可能有敏感文件）；Windows 沿用父目录继承的 ACL |

### 已知取舍（写清楚，避免误解）

- **v1 没有任何自动清理机制**，trash 只增不减，需要用户自己定期处置。这是刻意为之：任何"自动永久删除"的通路都会重新引入本次事故的风险。
- trash 目录里的文件是**原文件本体**（同卷 rename），不是副本。所以它占的是实打实的空间，不能用"删了 trash 就等于删了备份"这种想法去理解。

## 10. 代码结构与交付物

```
saferm/
  docs/saferm-design.md          # 本文
  src/
    go.mod
    cmd/saferm/main.go           # 参数解析、装配、退出码
    internal/config/             # 配置定位、TOML 解析（成熟库）、默认值合并
    internal/guard/              # §5 全部护栏 + 路径规范化（核心，优先实现）
    internal/volume/             # 卷/挂载点识别、同卷判定、trash 根解析
    internal/trash/              # 操作目录与清单、rename、统计扫描
    internal/ui/                 # 确认交互、TTY 判定、输出格式
  tests/                         # 端到端脚本（PowerShell + bash 各一份）
  build.ps1                      # Windows 构建 + 交叉编译
  Makefile                       # Linux/macOS 构建

```

### 10.1 依赖策略

原则：**凡是"基础设施"类的东西，一律用经过工业验证的成熟库，不自己造轮子**；凡是"本工具的独有逻辑"，才自己写。G5 里的"零依赖"指的是**运行时零依赖**（编译成单文件、目标机器不需要装任何东西），构建期引入纯 Go 的库不影响这一点。

两条硬约束：

- **不接受需要 CGO 的依赖**，否则交叉编译 `GOOS=windows/linux` 的能力就没了。
- 每个依赖都要能在 Windows 与 Linux 上同时工作，且要有活跃维护。

| 用途 | 选择 | 理由 |
|---|---|---|
| 命令行解析 | `spf13/pflag` | 需要 GNU 风格长短选项、`--` 结束符、`-rf` 这种短选项合并（标准库 `flag` 不支持）。pflag 是 k8s 生态在用的成熟实现 |
| 配置文件解析（TOML） | `pelletier/go-toml/v2` | **不手写 TOML 子集解析器**——那是最不值得自己造、又最容易静默出错的轮子。选它而不是 BurntSushi/toml 是实测结论：开启 `DisallowUnknownFields`（strict）后**键名写错也会报错**，且它与普通解码错误的 `String()` 都自带**行号 + 原文片段 + 出错位置的下划线**，正好满足 §7.1 的报错定位要求；BurntSushi 的位置信息只在语法/类型错误里有，`Undecoded()` 只能给出键名，定位不到行。纯 Go、无 CGO，交叉编译已验证 |
| TTY 检测 | `golang.org/x/term` | Go 官方子仓库，`term.IsTerminal(fd)` 比自己写 `GetConsoleMode`/`ioctl` 可靠 |
| Windows API（卷信息、短名展开、隐藏属性） | `golang.org/x/sys/windows` | 官方子仓库，比手写 lazy DLL 调用可靠；个别未导出的函数再用 `syscall` 兜底 |
| 通配符展开 | 标准库 `filepath.Glob` | 标准库足够，不引 doublestar 之类（不需要 `**`） |
| JSON 清单 | 标准库 `encoding/json` | — |
| 测试 | 标准库 `testing` + 原生 fuzz | 不引 testify 之类 |
| 原子写清单 | 自己写（临时文件 + `os.Rename`） | 十几行，且 rename 本来就在允许的写操作白名单里（C8） |

保持可审计的强不变量（C8）：v1 的代码里**不出现任何删除调用**（`os.Remove`、`os.RemoveAll`，以及 `DeleteFileW` / `RemoveDirectoryW` / `SHFileOperation`）。允许的文件系统写操作只有 `os.Rename`、`MkdirAll`、`WriteFile`（清单与标记）。
→ 在测试里加一条源码扫描断言，这样"这工具不会永久删数据"就是**可机械验证**的，而不是靠口碑。

- 构建产物：`build/saferm.exe`、`build/saferm_linux_amd64` 等，与同仓库 `filelist` 的约定保持一致。
- 交叉编译：`GOOS=windows/linux` × `amd64/arm64`。
- 语言约定：交互文案中文，日志与标识符英文（与同仓库约定一致）。

## 13. 与现有工作流的集成及边界

### 13.1 默认不动用户的别名

工具就是独立命令 `saferm`，装到 PATH 即可用。**默认不去覆盖 `rm` / `del` 别名**——`rm` 在不同 shell 下语义不同（pwsh 里 `rm` 本身就是 `Remove-Item` 的别名），擅自覆盖容易造成"以为在用真 rm"的混乱。别名配置放 README，由用户自己决定。

### 13.2 可选别名配置（README 给出，不默认执行）

- **PowerShell**：`rm` 是内置别名，直接 `Set-Alias rm saferm` 不生效，需要先 `Remove-Item Alias:rm -Force` 再 `Set-Alias rm saferm`（或 `Set-Alias -Option AllScope`）。建议写进 `$PROFILE`，并在旁边注释写明"这是 saferm，不是真 rm"。
- **Git Bash / WSL**：`alias rm=saferm`。注意 Git for Windows 自带 `rm.exe`，PATH 顺序要让 saferm 排在前面。
- **cmd**：`del` / `rd` 是内部命令，只能靠 `doskey`，效果有限，不折腾。

### 13.3 明确拦不住的（这就是边界）

`rimraf`、IDE 的删除、`npm run clean`、AI agent 自己拼出来的 `rm -rf`、资源管理器的删除——**统统拦不住**。这些只能靠改工作流习惯，或在 agent / 编辑器的命令权限配置里把危险删除命令设为"需人工确认"。

**别名只降低手滑概率，它不是对失控进程的防护。**

### 13.4 与 Git 的关系

- 本工具只**只读地**检测 `.git` 是否存在、仓库根在哪，**永不调用 `git reset` / `clean` / `checkout` / `restore`**。
- 特别地：**绝不要把 `saferm` 实现成 `git clean -fd` 的包装**。语义完全不同：`git clean` 只清未跟踪文件，且不可恢复。
- trash 只能救"本机的物理删除"，救不了误提交、救不了丢盘。及时 push 仍是不可替代的兜底。

## 14. 设计决策记录（已确认）

| # | 事项 | 决定 | 说明 / 被否掉的备选 |
|---|---|---|---|
| D1 | trash 是否套一层"操作目录"（§4.2） | **套一层** | 避免同名冲突歧义。否掉"直接镜像到 trash 根"——同一路径删两次会出现 `a`、`a~1`、`a~2`，手工恢复时无法判断该搬哪个 |
| D2 | 配置文件格式（§7.2） | **标准 TOML，用成熟库解析** | 否掉自研 TOML 子集解析器：那是最不值得自己造、又最容易静默出错的轮子。也否掉 JSON（不能写注释） |
| D3 | `-f` / `-y` 与护栏的关系（§5.2） | **护栏不可绕过** | 否掉"`-f` 一并绕过全部检查" |
| D4 | 是否保留 `--allow-dangerous` 逃生门 | **保留**，与 `--yes-i-am-sure` 同现时打印显著警告 | 不做环境变量解锁：把逃生门锁死只会逼人去用真 `rm` |
| D5 | Linux 是否纳入 v1 | **纳入** | 代码按跨平台写，仅增加测试成本 |
| D6 | PowerShell 下的通配符怎么解（§5.3） | **字面优先 + 工具自行展开 + 空匹配报错**，`--literal` 可关；展开结果必须重过全部护栏 | 否掉"只支持 stdin 管道"；否掉"完全不做" |
| D7 | Git 感知做到什么程度 | **v1 只做基础档**（检测 `.git`，目录与文件两种形态），增强档（调 `git status` 报未提交/未推送数量）留 v2、默认关 | 增强档更贴合"未推送提交被删"的事故场景，但要处理 git 缺失/超时，v1 不值得 |
| D8 | 危险级确认方式 | **手敲目标名**；确认级只输入 `yes` | 否掉"统一只输入 yes"，那样分级就没有意义 |
| D9 | 是否保留 `--yes-i-am-sure` | **保留**（危险级的唯一放行开关） | 否掉"不提供"，否则非交互环境永远处理不了大目录 |
| D10 | 危险级是否包含"目标在 cwd 之外" | **不做**（已否决） | 太吵：从固定目录启动时删任何别的路径都要手敲名字，结局是用户养成无脑加 `--yes-i-am-sure` 的习惯，危险级就形同虚设。危险级只由"体量"与"Git 工作区"这类客观高风险信号触发 |
