## 2026-10-06 21:19:18 — 第 1 步：guard 护栏 + 路径规范化

- 新增 `internal/guard`，落实设计文档 §5 全部护栏：
  - §5.0 路径规范化：绝对化/Clean → Windows 8.3 短名展开 → 不解析最后一级重解析点。
  - §5.1 第 1~8、11、12 条在 `guard.Check`；第 9、10 条（与回收目录的互为祖先关系）在 `guard.CheckTrashRelation`，须在解析出**最终**回收根后调用。
  - §5.2 绕过策略集中在 `Report.Add`：危险路径类可被 `--allow-dangerous` 降级为警告；参数错误类任何开关都不可绕过。
  - 受保护路径分两种力度：`subtree`（系统目录，整棵子树都不可删）与仅自身（用户主目录本身），否则工具连"删下载目录里的文件"都做不到。
- `Violations.Error()` 的文案要求写明"原数据未改动"（C7），空参数提示 `saferm '$null'` 的引号写法。
- **修复一个 Linux 上才会暴露的真 bug**：`platform.VolumeRoot` 原先用 `Dir(p)` 求父目录的卷，导致挂载点自身（如 `/data`）被误判为 `/`，会让"目标是卷根"漏检、并让回收根选错卷。卷的判定是纯字面的，已改为直接对目标路径求最深的已存在祖先。回归测试 `TestVolumeRootOfMountPointIsItself`。
- 验证：
  - `gofmt -l .` 无输出、`go vet ./...` 干净。
  - Windows 本机与 Linux（`root@192.168.1.118`，`/data` 为独立挂载）全部测试通过。
  - 8.3 短名绕过测试在本机 Windows 上**真实执行**（非跳过）：证明"字面比较会认为 `C:\PROGRA~1` 与 `C:\Program Files` 不同"，而 guard 仍能拒绝。

## 2026-10-06 21:12:33 — 第 0 步：立模块、定依赖、交叉编译冒烟

- 新增设计文档 `docs/saferm-design.md`（v0.3）：§5.1 为护栏清单（即 guard 模块测试用例表），§14 为已确认决策记录。
- 新增 `src/` Go 模块（module `saferm`），依赖策略定为**运行时零依赖、构建期用成熟库**。
- 新增 `internal/platform`：卷挂载点识别、同卷判定、Windows 8.3 短名展开、重解析点识别、回收根隐藏属性。
  - Windows 走 `golang.org/x/sys/windows`（`GetVolumePathNameW` / `GetLongPathNameW` / `GetFileAttributesW` / `SetFileAttributesW`），不手写 lazy DLL 调用。
  - Linux 走 `/proc/self/mounts` 取挂载点 + `st_dev` 判同卷。
  - 关键设计：一律针对**父目录链上最深的已存在祖先**求卷，因此尚未创建的回收根也能判定同卷。
- 新增 `cmd/saferm` 骨架，仅支持 `-V/--version`，其余待后续步骤。
- 验证：
  - `gofmt -l .` 无输出、`go vet ./...` 干净。
  - 交叉编译 windows/amd64、linux/amd64、linux/arm64 全部通过。
  - `internal/platform` 测试在本机 Windows 与 Linux（`root@192.168.1.118`）上均通过，含 C:/D: 跨卷必须判为不同卷的断言。
- 注意：`go build` 需要 `-buildvcs=false`，否则在本仓库（大 repo）里会因读写 `.git` 被沙箱拒绝。
