# 机械师 G7 鼠标 WebHID 协议分析

本文基于 `temp/` 下的官方网页驱动、动态加载的设备定义，以及一次只读 HID 实测。实测设备通过 2.4G 接收器连接，识别结果为 **L4165B / G7**。

## 1. 设备标识

| 项目 | 值 |
| --- | --- |
| 厂商标识 VID | `0x320F`，十进制 `12815` |
| 有线 PID | `0x22A4`，十进制 `8868` |
| 2.4G PID | `0x226F`，十进制 `8815` |
| 设备 CID | `12` / `0x0C` |
| 目标 HID Usage Page | `0xFF1C`，十进制 `65308` |
| 目标 HID Usage | `0x92`，十进制 `146` |
| 配置报文 Report ID | `4` |
| 固件报文 Report ID | `5` |
| 配置区长度 | `128` 字节 |
| 键位区长度 | `128` 字节 |
| 配置文件数量 | `1` |

2.4G 接收器在 Windows 上会暴露多个 HID collection；实测目标 collection 为 `MI_01&Col02`，其 `usagePage=0xFF1C`、`usage=0x92`。枚举时不要只按 VID/PID 打开，应同时匹配 Usage Page 和 Usage，避免打开普通鼠标接口。

## 2. 报文总体结构

普通配置使用 Output Report ID `4`，长度为 63 字节；设备通过 Input Report ID `4` 响应。

WebHID 调用形式：

```js
device.sendReport(4, payload63)
```

若使用 `node-hid`，需要把 Report ID 放在第一个字节：

```js
device.write([4, ...payload63])
```

63 字节 payload 结构如下：

| Payload 偏移 | 长度 | 含义 |
| --- | --- | --- |
| 0 | 1 | 固定 `0x00` |
| 1 | 1 | 固定 `0x00` |
| 2 | 1 | 命令码 |
| 3 | 1 | 长度/命令参数：内存读写时为数据区长度，特殊控制命令使用固定值 |
| 4 | 1 | 偏移低字节 |
| 5 | 1 | 偏移高字节，小端 |
| 6 | 1 | 固定 `0x00` |
| 7 起 | N | 数据区；特殊控制命令也可能无数据 |
| 31 | 1 | 嵌套/保留字节，G7 实测为 `0x00` |

响应会回显命令码、长度和偏移，数据同样从 payload 偏移 7 开始。

### 传输分片

- 2.4G：单次数据区最大 `24` 字节，即长度字段 `0x18`。
- 有线：官方通用代码使用最大 `56` 字节。
- 读取 128 字节时，2.4G 分为 6 片：`24 + 24 + 24 + 24 + 24 + 8`。
- 写入时，官方驱动会先发送开始事务命令，再发送数据，最后发送结束事务命令。

## 3. 命令码

| 命令码 | 方向 | 含义 |
| --- | --- | --- |
| `0x01` | 输出 | 配置写入开始事务 |
| `0x02` | 输出 | 配置写入结束事务 |
| `0x03` | 读 | 设备信息，官方长度 `34` 字节 |
| `0x05` | 读 | 读取功能配置区；也可读取当前配置编号 |
| `0x06` | 写 | 写入功能配置区 |
| `0x07` | 读 | 读取默认/出厂键位区 |
| `0x08` | 读 | 读取当前键位区 |
| `0x09` | 写 | 写入当前键位区 |
| `0x19` | 输出 | 状态查询，官方在电量查询前发送 |
| `0x1A` | 输出 | 电量查询 |
| `0x30` | 输出 | 识别设备，返回 Magic 和 CID |
| `0xAA` | 输出 | 固件相关流程使用 |

## 4. 设备识别

请求：

```text
04 00 00 30 10 00 00 00 ...
```

实测响应：

```text
04 00 00 30 10 00 00 00 AA 55 0C ...
```

数据区前三个字节为：

| 数据区偏移 | 含义 | 实测值 |
| --- | --- | --- |
| 0 | Magic 1 | `0xAA` |
| 1 | Magic 2 | `0x55` |
| 2 | CID | `0x0C` = 12 |

官方设备定义中，CID `12` 对应 L4165B/G7。

## 5. 电量查询

官方顺序是先发送 `0x19`，再发送 `0x1A`。

`0x19` 请求：

```text
04 00 00 19 18 00 00 00 ...
```

`0x1A` 请求：

```text
04 00 00 1A 06 00 00 00 ...
```

实测响应：

```text
04 00 00 1A 06 00 00 00 5D ...
```

- 电量位于数据区偏移 0，即 payload 偏移 7。
- `0x5D` = `93`，即 93%。
- 有线模式下，官方 UI 直接显示 100%。
- 当前驱动代码中未发现独立的“正在充电”标志；“充电中”文案存在，但未在该 HID 通信模块中解析。

## 6. 键位区

### 6.1 默认键位与当前键位

- `0x07`：默认/出厂键位区。
- `0x08`：当前键位区。
- `0x09`：写入当前键位区。

实测默认键位区前 24 字节：

```text
10 01 00  10 04 00  10 02 00  10 10 00  10 08 00  13 03 00  A0 30 00  A0 31 00
```

实测当前键位区前 24 字节：

```text
10 01 00  10 04 00  10 02 00  10 10 00  20 10 35  13 03 00  A0 30 00  A0 31 00
```

### 6.2 三字节键值格式

每个键位项占 3 字节：

```text
类型  参数1  参数2
```

常见类型：

| 类型 | 含义 | 示例 |
| --- | --- | --- |
| `0x10` | 鼠标按键 | `10 01 00` = 左键 |
| `0x13` | DPI 控制 | `13 03 00` = DPI 循环 |
| `0x20` | 键盘按键/组合键 | `20 10 35` = Right Ctrl + Grave/Tilde |
| `0x30` | Consumer/媒体键 | `30 EA 00` = 音量减 |
| `0x70`/`0x71` | 宏引用 |
| `0xA0` | 系统/虚拟键，官方 G7 物理键列表未暴露 |

鼠标默认按键：

| 键位项 | 含义 |
| --- | --- |
| `10 01 00` | 左键 |
| `10 02 00` | 右键 |
| `10 04 00` | 中键 |
| `10 08 00` | 后退 |
| `10 10 00` | 前进 |
| `13 03 00` | DPI 循环 |

键盘项中：

- `0x20` 为键盘类型。
- 第二字节为 modifier 位掩码，例如 `0x10` 是 Right Ctrl。
- 第三字节为 HID Keyboard Usage，例如 `0x35` 是 Grave Accent / Tilde。

媒体键中：

- `0x30` 为 Consumer 类型。
- 后两字节组成 Consumer Usage，小端。

### 6.3 写入键位

官方逻辑不是只写单个键位项，而是：

1. 读取完整 128 字节当前键位区。
2. 在本地按 3 字节一项查找旧键值。
3. 替换目标项的 3 字节。
4. 发送命令 `0x01` 开始事务。
5. 分片发送命令 `0x09`，携带完整 128 字节。
6. 发送命令 `0x02` 结束事务。
7. 用设备响应回写本地状态。

## 7. 功能配置区

功能配置区通过 `0x05` 读取、`0x06` 写入。

### 7.1 固定字段

| 偏移 | 长度 | 含义 |
| --- | --- | --- |
| 0 | 1 | 当前配置编号；单配置设备实测为 `0x00` |
| 11 | 1 | 回报率 |
| 12 | 1 | 当前 DPI 档位，从 0 开始 |
| 13 | 1 | 静默高度 / Lift-Off Distance |
| 14 起 | 54 字节 | 6 组 DPI 档位数据 |

### 7.2 回报率

| 值 | 回报率 |
| --- | --- |
| `0` | 125Hz |
| `1` | 250Hz |
| `2` | 500Hz |
| `3` | 1000Hz |

实测偏移 11 为 `0x03`，即 1000Hz。

### 7.3 静默高度

| 值 | 含义 |
| --- | --- |
| `0` | 低 |
| `1` | 中 |
| `2` | 高 |

实测偏移 13 为 `0x00`。

### 7.4 DPI 档位

每组 DPI 占 9 字节，共 6 组。组起始偏移：

```text
14, 23, 32, 41, 50, 59
```

组内字段：

| 组内偏移 | 含义 |
| --- | --- |
| 0 | 启用状态：`1` 启用，`0` 禁用 |
| 2 | DPI 原始值低字节 |
| 3 | DPI 原始值高字节，L4165B 通常为 0 |
| 6 | R |
| 7 | G |
| 8 | B |

L4165B 的 DPI 解码公式：

```text
raw <= 159: DPI = (raw + 1) * 100
raw > 159 : DPI = 16000 + (raw - 159) * 200
```

编码公式：

```text
DPI <= 16000: raw = DPI / 100 - 1
DPI > 16000 : raw = 159 + (DPI - 16000) / 200
```

实测原始值与 DPI：

| 档位 | 原始值 | 启用状态 | 颜色 | DPI |
| --- | --- | --- | --- | --- |
| 1 | `0x07` | 禁用 | `#FF0000` | 800 |
| 2 | `0x0F` | 启用 | `#00FF00` | 1600 |
| 3 | `0x17` | 启用，当前档 | `#0000FF` | 2400 |
| 4 | `0x1F` | 启用 | `#FFFF00` | 3200 |
| 5 | `0x3F` | 启用 | `#FF00FF` | 6400 |
| 6 | `0x9F` | 禁用 | `#FF6400` | 16000 |

G7 设备定义中 `lamplightBol=0`，没有实际灯效控制；这些颜色主要用于驱动界面中的 DPI 档位标识。

> 注意：官方 UI 写 DPI 时调用了一个四字节写入辅助函数，传入位置为 `rawPos, rawPos+1`，数据为同一个原始值。工厂数据中原始值位于 `rawPos`，相邻保留字节布局与该调用并不完全一致。实现写入前应先做一次写后回读验证，不能在未验证时批量写入。

## 8. 设备信息区

命令 `0x03` 读取 34 字节，实测为：

```text
AA 55 0C 00 ... 00
```

可确认前三个字节仍是 `0xAA 0x55 0x0C`。官方 G7 通信模块未对其余字段做进一步解析，可能是固件版本或硬件参数保留区。

## 9. 加密与固件升级

- G7 设备定义中的 `secretKey` 为 `0`，运行时配置区和键位区均为明文，不需要 AES/Blowfish 解密。
- bundle 中引入了 CryptoJS、Blowfish 等代码，属于其他设备或历史兼容逻辑。
- 官方固件 `.bin` 文件前 8 字节为文件头，后续数据使用 64 字节 XOR 表解密。
- 固件升级使用 Report ID `5`，包含独立分片、CRC 和升级状态机。
- 本地工具第一阶段不建议实现固件升级，避免刷写失败；应先完成只读、配置写入和键位写入。

## 10. 本地工具实现建议

推荐分两阶段。

### 阶段一：Node.js 只读/写入原型

使用 `node-hid`：

1. 枚举 `VID=0x320F`、`usagePage=0xFF1C`、`usage=0x92` 的 collection。
2. 打开设备并发送 `0x30`，校验 `AA 55 0C`。
3. 发送 `0x19`、`0x1A` 获取电量。
4. 读取并解析：
   - `0x07` 默认键位区；
   - `0x08` 当前键位区；
   - `0x05` 功能配置区。
5. 所有写入先做 dry-run diff，只显示将要修改的字节。
6. 完成单字段写入并立即回读校验。

### 阶段二：本地图形界面

有两个可选路线：

| 方案 | 优点 | 缺点 | 建议 |
| --- | --- | --- | --- |
| Electron + `node-hid` | 全栈 JavaScript，可复用网页驱动 UI 和现有项目 | 原生模块需按 Electron ABI rebuild，安装包较大 | 如果希望快速复刻官方网页驱动，选它 |
| Tauri + Rust `hidapi` | 安装包小，HID 后端稳定，权限边界清晰 | 需要写 Rust，前端通过命令桥接 HID | 更适合长期维护的本地工具 |

我建议先用 Node CLI 验证协议，再做图形界面。图形界面首版功能限定为：设备识别、电量、当前键位展示、按键重映射、DPI 档位、回报率、静默高度；宏编辑和固件升级放到后续版本。

## 11. 安全与验证要求

- 所有写入都必须保留原始 128 字节快照。
- 写入前显示 diff，写入后立即重新读取并逐字节比对。
- 禁止在未识别 CID 的设备上发送写入命令。
- 一次只测试一个字段，建议顺序：回报率 → 静默高度 → DPI → 单键映射。
- 若响应超时或命令码不匹配，立即停止，不自动重试写入。
