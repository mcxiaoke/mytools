# 变更摘要（2026-09-14）

## 自身保护改为路径级硬性不变量（15:47）

**背景**：初版要求"updater 必须运行在 target 之外"，这是把责任推给调用方的约定，
不可靠。运行中的 exe 在 Windows 下被独占锁定，这是 updater 自己就能知道的信息。

**改动**

- 启动时取 `os.Executable()`，若其位于 `--target` 内，就把该**精确相对路径**
  登记为无条件跳过项（`config.selfRel`），与保护清单完全解耦。
- 路径比较大小写不敏感（Windows 文件系统语义），包内写 `Updater.exe` 同样拦截。
- 不再按 basename 全局保护，避免误伤 `sub/updater.exe` 这类异路径同名文件。
- `applyPlan` 增加纵深防御：写入前再次校验目标路径是否为自身，命中即跳过并记日志。
- 保护清单文件本身同样按路径解析（`config.keepRel`），取代原先的字面量规则。
- 新增 `relWithin` / `cleanAbs` 工具函数（处理 `\\?\` 前缀与大小写）。
- README 删除"必须放在 target 之外"的约定，改为说明两种放置位置的差异。

**验证**

`python temp/verify.py` — **26/26 通过**，新增场景 `scenario_self_inside_target`：
把 updater 复制进 target 内运行，断言自身二进制完全未被改动、大小写变体条目被拒、
`sub/updater.exe` 正常写入、其余文件与配置保护行为不变、仍能重新拉起应用。

## updater 通用 Windows 自动更新工具首版实现

**新增**

- `main.go`：Go 单文件实现，零第三方依赖。
- `go.mod`、`build.sh`：模块定义与构建脚本（`-s -w -H=windowsgui`，不使用 UPX）。
- `README.md`、`.updatekeep.example`：调用契约、保护清单语法、Flutter 接入示例。
- `temp/`：端到端验证脚本（`setup.py` 构造环境，`verify.py` 跑 17 项断言）。

**关键设计决策**

- 采用独立 `updater.exe` 方案：主程序退出前拉起，由它等待 PID 释放句柄后覆盖再重启。
- **updater 不在 target 目录内运行**：否则更新包含 `updater.exe` 时会出现自覆盖自锁。
- 保护清单走 `<target>/.updatekeep` 清单文件（随应用打包）+ `--keep` CLI 叠加。
- 更新语义定为"只覆盖、不删除"，keep 命中路径既不覆盖也不新增。
- 逐文件 `临时文件 + rename` 原子替换，替代原先的 `O_TRUNC` 直写，避免半截文件。
- 失败兜底：更新失败仍拉起旧版本 + 写日志 + 退出码非 0，避免"应用消失"。
- 内置保护 `updater.exe` 与 `.updatekeep` 自身。

**修复的设计缺陷（相对参考方案）**

| 问题 | 处理 |
| --- | --- |
| 配置/数据保护完全缺失 | 引入 `.updatekeep` 清单 + glob/目录前缀匹配 |
| Zip Slip 路径穿越 | `safeRelPath` 归一化拦截 `..`、绝对路径、盘符，并在写入前二次校验前缀 |
| updater 自覆盖自锁 | 内置自保护规则（15:47 已升级为路径级硬性不变量，不再要求放在 target 之外） |
| 等待逻辑返回值被忽略 | 超时即失败并兜底拉起；区分"进程不存在"与"拒绝访问" |
| 非原子覆盖 | 写同目录临时文件后 `rename` 替换，带可配置重试退避 |
| 无日志无兜底 | 全程写日志文件；失败兜底拉起旧版 |
| 拉起子进程 cwd 错误 | 设置 `cmd.Dir = target`，`DETACHED_PROCESS` 不继承句柄 |
| zip 句柄未释放导致删包失败 | `applyPlan` 后显式 `zr.Close()` 再删除更新包 |
