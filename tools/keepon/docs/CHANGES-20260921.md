# 变更记录 2026-09-21

## 修复：UntilTime 模式启动恢复忽略用户选择的时刻（11:52 GMT+8）

**问题**：`App.RestoreSavedMode()` 在恢复「保持至指定时刻」模式时硬编码 `SetUntilTime("18:00")`，既不是用户上次实际选择的时刻，也不是预设列表中的值。用户新增 `00:00` 预设后，若开启「启动时恢复上次模式」，重启总会恢复成 18:00。

### 修改

- **`Models/AppConfig.cs`**：
  - 新增 `LastUntilTime` 属性，记录上次使用「保持至指定时刻」模式时的实际目标时刻（HH:mm）。
  - `Sanitize()` 对该字段做规范化：非法值清空，`8:5` 这类输入归一化为 `08:05`，避免脏数据被当成有效时刻恢复。
  - 新增 `ResolveUntilTime()`：优先返回上次使用的时刻，缺失或非法时回退到预设列表首项。
- **`App.xaml.cs`**：
  - `RestoreSavedMode()` 的 UntilTime 分支改用 `_config.ResolveUntilTime()`，不再硬编码 18:00。
  - `PersistMode()` 在 UntilTime 模式下记录 `_controller.ExpireTime` 的时刻到 `LastUntilTime`；仅在该模式下更新，避免切到其他模式后覆盖有效值。

### 注释说明（按用户要求暂不修改）

- **`Views/SettingsWindow.xaml.cs`**：标注「保持至」输入框初值取预设首项，因此预设为 `18:00, 20:00, 22:00, 00:00` 时总是预填 `18:00`；并注明如需改为上次使用的时刻应使用 `ResolveUntilTime()`。
- **`App.xaml.cs`（托盘菜单）**：标注 `00:00` 预设的标签「至 00:00」实际含义是次日零点，容易被读成今天零点；如需更明确可追加「（次日）」后缀。
- **`Services/AwakeController.cs`**：标注 `SetUntilTime` 使用 `<=` 判定，恰好在目标时刻整点调用时会顺延到次日同一时刻（即保持满 24 小时），属该语义下的合理结果。

### 验证结果

- MSBuild Release 全量重建通过，0 error 0 warning。
- `verify_keepon.ps1` 44 项检查全部通过。
- 新增 `keepon-cli untiltime` 诊断子命令，覆盖两部分：
  - **时刻解析**：`00:00` / `00:01` / `18:00` / `20:00` / `22:00` / `23:59` 全部符合「取今日该时刻，已过则顺延次日」；`00:00` 正确解析为次日零点。
  - **持久化恢复**：保存 `00:00` 恢复 `00:00`；未保存时回退预设首项；脏数据 `25:99` 被清理并回退；`8:5` 规范化为 `08:05`。
- **真实端到端复测**：写入 `Mode=UntilTime` + `LastUntilTime=00:00` + `RestoreModeOnStartup=true`，启动后日志显示 `已切换到保持唤醒至 2026-09-22 00:00`（而非旧的 18:00），配置文件中 `LastUntilTime` 保持 `00:00`。测试后已还原配置。

## 代码整理：消除魔法数字与重复实例化（11:30 GMT+8）

**背景**：用户调整定时/时段预设时，发现默认值在多处重复书写（改一处要同步改四处，且已出现漏改），且大量边界数字与 UI 颜色以裸字面量散落在模型、服务与界面三层。

### 新增

- **`Models/ConfigDefaults.cs`**：配置默认值与取值边界的唯一权威来源。集中定义时长/电池阈值/退出缓冲的上下限与默认值、默认预设列表、热键与配置版本号，并提供 `ClampDurationMinutes` / `ClampBatteryThreshold` / `ClampProcessExitDelaySeconds` / `IsValidDurationMinutes` 等收敛与校验方法。
- **`Services/TextListParser.cs`**：用户列表输入的统一解析入口。收口分隔符数组（中英文逗号/分号/空格/制表符），提供 `Split` / `ParseMinutes` / `ParseTimes` / `ParseProcessNames`。
- **`Views/BadgeStyle.cs`**：状态徽标配色的命名常量类型，4 组配色（Warning/Success/Active/Neutral），Brush 在静态构造时一次性创建并 `Freeze()`。

### 修改

- **`Models/AppConfig.cs`**：属性初始化与 `Sanitize()` 回退分支统一引用 `ConfigDefaults`，消除 3 处重复预设列表字面量；清洗逻辑拆分为 `SanitizeTimerPresets` / `SanitizeUntilTimePresets` 两个语义化私有方法。
- **`Services/AwakeController.cs`**：心跳周期提取为 `TickInterval`，轮询间隔加注释说明计次含义；删除重复实现的私有 `ClampExitDelay`，改用 `ConfigDefaults.ClampProcessExitDelaySeconds`。
- **`Views/SettingsWindow.xaml.cs`**：`ParseIntList` / `ParseTimeList` 委托给 `TextListParser`（消除两段重复解析循环）；进程输入的多值切分改用 `TextListParser.Split`；保存校验分支改用 `ConfigDefaults` 的边界常量与收敛方法；状态徽标改用 `BadgeStyle`，不再每次刷新都 `new SolidColorBrush` 并解析颜色字符串。
- **`Services/PowerNative.cs`**：`BatteryFlag` / `ACLineStatus` 的哨兵值与位标志（128/255/1/0x04/0x08）提取为具名常量，电量未知哨兵值公开为 `UnknownBatteryPercent`。
- **`Services/HotkeyService.cs`**：虚拟键码基数（A-Z / 0-9 / F1-F24）与手势分隔符提取为具名常量；删除未使用的 `_keyMap` 字段与空方法 `BuildKeyMap`。
- **`Services/ProcessHelper.cs`**：窗口标题截断长度（28 / 25）提取为 `MaxDisplayNameLength` 与 `TruncatedNameLength`。
- **`Services/StatusFormatter.cs`**：小时换算的 `60` 提取为 `MinutesPerHour`。
- **`App.xaml.cs`**：自定义时长对话框的提示文案与校验改用 `ConfigDefaults`，不再硬编码 1 / 1440。
- **`tools/KeepOn.Cli/KeepOn.Cli.csproj`**：编译列表补充 `ConfigDefaults.cs` 与 `TextListParser.cs`。

### 修复

- **`Sanitize()` 时刻预设回退丢失 `00:00`**：原实现当 `UntilTimePresets` 全为非法值时，回退到硬编码的 `18:00, 20:00, 22:00`（缺 `00:00`），与属性初始化不一致。统一后回退到 `ConfigDefaults.UntilTimePresets`，`00:00` 得以保留。
- **手改遗留的格式问题**：`Sanitize()` 中的重复分号 `;;`、逗号后缺空格 `720,1440`、行尾多余空格等。
- **行为保持一致**：`ClampDurationMinutes` 对非法（<=0）值刻意回退为**默认时长**而非下限 1 分钟，保留原有语义（避免用户误填 0 被静默改成 1 分钟）。

### 验证结果

- `verify_keepon.ps1` 44 项检查全部通过（exit code 0）。

## KeepOn 保持唤醒应用首次交付

**背景**：参考 `C:\Home\Projects\CarroDesk` 的 Awake 模块，独立实现一个保持唤醒工具，功能对齐 PowerToys Awake，目标框架 .NET Framework 4.8。

### 新增

- **项目骨架**：`KeepOn.sln`、`src/KeepOn.csproj`（net48 / WPF / WinExe）、`app.manifest`（PerMonitorV2 DPI 感知、asInvoker 权限）、`.gitignore`。
- **核心服务层**：
  - `PowerNative`：`SetThreadExecutionState` 与 `GetSystemPowerStatus` 的 P/Invoke 封装，含电源状态快照与"是否应挂起"判定。
  - `AwakeController`：核心状态机，覆盖 Passive / Indefinite / Timed / UntilTime 四种模式，负责电源请求应用与释放、倒计时到期、电池挂起、进程联动与退出缓冲。
  - `ProcessHelper`：进程名归一化（大小写、路径、扩展名差异容错）、批量去重、运行实例发现。
  - `ConfigService`：JSON 原子写入（临时文件 + Replace），损坏配置自动备份降级。
  - `HotkeyService`：`RegisterHotKey` 封装与 "Win+Shift+W" 形式手势解析，含 A-Z / 0-9 / F1-F24 / OEM 符号键映射。
  - `StartupManager`：写 `HKCU\...\Run` 实现开机自启，无需管理员权限。
  - `StatusFormatter`：托盘标题、悬停提示、状态徽标的统一文本格式化。
  - `Paths`：漫游目录与便携模式（`portable.marker`）路径解析。
  - `Log`：按天切分、限体积的轻量日志。
- **界面层**：
  - `App.xaml(.cs)`：托盘图标与完整右键菜单（模式切换、定时预设、至指定时刻、屏幕常亮、电池暂停、设置、日志目录、退出），双击托盘打开设置。
  - `SettingsWindow`：工作模式、电源策略、托盘菜单预设、智能进程联动、关于五张卡片；底部恢复默认 / 保存并应用 / 关闭。
  - `InputDialog`：自定义分钟数与自定义时刻的轻量输入框。
  - `CommonStyles.xaml`：卡片、主/次按钮、窄滚动条等共享样式。
- **入口与命令行**：`Program.Main` 提供单实例互斥保护；`--minimized` / `--help` / `--version` 参数。
- **验证工具**：`tools/KeepOn.Cli`（无界面，复用服务层源码），支持 `status` / `verify` / `hold` / `display` / `process` 子命令。
- **自动化脚本**（`temp/`）：
  - `render_keepon_windows.ps1` + `render_keepon_inner.ps1`：基于 `RenderTargetBitmap` 的离屏渲染，与显示器分辨率及 DPI 无关。
  - `verify_keepon.ps1`：40 项检查，覆盖构建产物、程序集类型、纯逻辑（进程名/时刻归一化、配置清洗、热键解析、状态格式化）与电源请求端到端验证。

### 关键实现决策

- **单文件交付**：通过 Costura.Fody 内嵌 `Hardcodet.NotifyIcon.Wpf` 与 `Newtonsoft.Json`，发布只需拷贝 `KeepOn.exe`。
- **入口点保留在 `Program.cs`**：`App.xaml` 以 `Resource` 方式编译（非 `ApplicationDefinition`），以便在 WPF 启动前完成单实例互斥与命令行解析；共享样式改由 `App` 构造函数代码加载。
- **窗口尺寸自适应**：`SettingsWindow` 在 `Loaded` 时把尺寸收敛到 `SystemParameters.WorkArea`，避免高 DPI 或小屏设备上底部按钮不可达；渲染场景通过 `_suppressClamp` 跳过该限制以截取完整高度。
- **状态一致性**：所有状态变更收敛在 UI 线程，界面与托盘共享 `AwakeController` 的同一份状态与事件。
- **电池挂起标志归属**：`_isBatteryPaused` 刻意不在 `SetPassive` 中重置，避免下一次轮询立刻重新置起造成状态抖动（沿用参考实现的既有结论）。
- **尊重用户意图**：手动关闭后置位 `_userSuppressedProcessLink`，在进程联动名单全部退出后才解除，防止用户的关闭动作被下一次轮询反转。

- 离屏渲染截图确认设置窗口五张卡片与底部三个按钮完整显示、无裁切。

### 已知限制

- 电池保护分支在本机（无电池的台式机）无法实测。
- 托盘图标与气泡通知无法在无头环境自动化验证，仅通过日志与进程存活确认。
