# CHANGES-20260918

## 运维面板：命令策略改为关键词黑名单（2026-09-18 15:50 GMT+8）

### 背景

原实现是 allowlist 模式：内置一长串只读命令正则，未列出的命令一律拒绝，另外还有
`free` 模式与 `allow`/`deny` 两个正则列表。问题有两个：

1. **默认太紧**：面板的主场景是「改完配置后 `systemctl restart xxx`」，但这条命令
   不在内置白名单里，必须先写正则才能用。默认拦掉主场景会把人推向 `mode: free`。
2. **概念太多**：白名单 + 自由模式 + allow 正则 + deny 正则，四套东西叠加，
   使用者要理解优先级、锚定写法与 nil/空列表语义，成本高于收益。

### 改动

命令边界简化为**一条规则**：命令以黑名单关键词开头即被拒绝，其余一律放行。

- **新增纯函数 `matchBlacklist(cmd, keywords) (string, bool)`**：只做大小写不敏感的前缀
  比较，无状态、无正则、无 I/O。返回命中的关键词便于报错与日志。
- **内置极简 blacklist**（26 项）：`rm` `dd` `mkfs` `shred` `truncate` `chmod` `chown`
  `chattr` `mount` `umount` `shutdown` `reboot` `halt` `poweroff` `kill` `pkill`
  `useradd` `userdel` `passwd` `crontab` `iptables` `ufw` `apt` `yum` `dnf` `pacman`。
  只覆盖「会毁数据 / 改权限 / 改主机 / 重写包库」的命令。
- **新增 `ops.blacklist` 配置项**：关键词**追加**到内置集合，用户可在配置文件手工增补。
- **删除 `ops.mode`（allowlist/free）、`ops.allow`、`ops.deny`** 及相关正则编译、
  `builtinAllowlists`、`defaultDenyPatterns`、`FreeMode()`、`OpsFreeMode()`、
  `ClientConfig.Mode`。前端不再下发 `mode` 字段。
- **保留两条必要的护栏**，因为前缀匹配单独存在时不可靠：
  - 元字符扫描（`;` `&&` `|` `` ` `` `$(` `>` `<` `&` 换行）**先于**匹配执行，
    否则 `ls; rm -rf /` 会凭第一个词蒙混过关；
  - 提权前缀（`sudo` `doas` `pkexec` `nohup` 等）匹配前剥离，否则 `sudo rm -rf /` 绕过。
- **`mv` 不列入内置**：前缀匹配会连 `mvn` 一起拒绝，而移动文件是常规操作；
  需要时由用户加入 `ops.blacklist`。

### 影响与取舍

- 面板默认从「白名单放行」变为「黑名单拦截」，即默认放行任意命令。
  这是刻意的：黑名单的定位是**防手滑**，不是防攻击。README 的「能力边界」已相应更新，
  并提示不要将面板暴露在不可信网络。
- 行为更可预测：前缀匹配无锚定歧义，`grep rm /var/log/syslog`、`ls /data/rmtest`
  这类正常读取不会被误伤（有测试覆盖）。

## 运维面板：命令执行改为流式，修复长驻命令卡死（2026-09-18 14:00 GMT+8）

### 问题

执行 `tail -f` 这类持续输出、永不退出的命令时，面板会永久停留在「执行中」，
输入框被禁用且 ⏹ 无效，只能刷新页面。三个缺陷叠加造成：

1. **输出被缓冲到进程结束**：`RunExec` 把 stdout/stderr 指向 `bytes.Buffer`，
   然后 `cmd.Run()` 阻塞等待退出，最后一次性发送。长驻命令因此**一帧都不会到达前端**。
2. **超时不杀进程组**：使用 `exec.CommandContext`，其取消只作用于直接子进程；
   正确的 `killProcessGroup`（`Setpgid` + 负 PID）只在 PTY 路径被调用，exec 路径从未使用。
3. **⏹ 按钮无对象**：`currentSID` 仅在 `ready` 帧赋值，而 `ready`
   只为 PTY 会话下发，exec 路径从不发送——按钮点了等于没点。

### 修复

- **流式执行**：新增 `StartExec` 返回 `execHandle`，用 `StdoutPipe`/`StderrPipe`
  边读边通过 WebSocket 推送；`streamExec` 同时镜像到会话环形缓冲，断线重连可重放。
- **不再依赖 `CommandContext`**：改用显式 deadline + `killProcessGroup`，超时终止整个进程组。
- **exec 会话下发 `sid`**：新增 `ready` 帧，⏹ 现在对 exec 与 PTY 都可用；
  `handleSignal` 分派到 `stopProc`（exec）或 `sendSignal`（PTY）。
- **前端本地兜底**：客户端按 `timeoutSeconds`（新增下发字段）自设看门狗，
  即使帧丢失或连接假死也能恢复输入，不再永久卡死。
- **状态语义化**：`exit` 帧新增 `timedOut`/`killed`，
  前端显示「超时已终止」「已中断」而非裸退出码。
- **Windows 进程树终止**：`proc.Kill()` 只杀直接子进程，`cmd.exe /C`
  派生的孙进程（如 `tail.exe`）会存活。改用 `taskkill /F /T` 遍历整棵树。
- **管道读端主动关闭**：`closePipes` 在终止后释放读取方，
  避免 Windows 上孙进程持有写端导致读取永不返回 EOF。

### 测试

新增 4 个 Go 测试，均在 Linux 上通过（Windows 因需要 POSIX shell 而跳过）：

| 测试 | 覆盖 |
|------|------|
| `TestStreamExec_DeliversOutputBeforeExit` | 输出必须在进程退出**之前**到达（1s 内） |
| `TestRunExec_InfiniteOutputIsCutOff` | `yes` 无限输出：超时终止、输出截断、无挂起 |
| `TestRunExec_KillStopsCommand` | ⏹ 的服务端路径 |
| `TestRunExec_NoOrphanedChildren` | 超时后无孤儿进程 |

端到端验证（真实 WebSocket + 真实文件增长）5/5：首个输出帧 **32ms** 到达（此前永不到达）、
5s 超时精确触发并带 `timedOut=true`、超时后 35ms 内可执行新命令、无孤儿进程。
Linux 侧 62 个测试全部通过，Playwright 46/46。

## 运维面板（Ops Panel）上线（2026-09-18 11:15 GMT+8）

新增可选的浏览器内命令执行面板，闭合「在 filelist 中改完配置 → 立即执行命令使其生效」的工作流断点。默认关闭，需显式启用。

### 后端：独立子包 `internal/ops`

- **独立 Go 子包**（约 1200 行）承载全部业务逻辑，通过 `internal/` 强制编译期边界：外部模块无法导入，且它天然无法反向依赖主包，依赖方向单向（main → ops）。
- **接口注入而非直接依赖**：`Logger` 与 `PathResolver` 接口声明在 ops 包内（Go 惯例：接口定义在消费方），由主包通过 `ops_adapter.go`（约 40 行）适配既有的 `log` 与 `indexer`。ops 包不导入 `indexer`、`Server` 或 `webFS`，其单元测试可用假实现完全脱离 filelist 运行。
- **双执行后端**：
  - 一次性 `exec`：管道收集输出，输出干净、**可获取真实退出码**（无需 `; echo $?` 哨兵），跨平台可用；
  - 交互式 `pty`：基于 `creack/pty` 的真终端，支持 `vim`/`top`/`journalctl -f`，仅 Unix。
- **统一 WebSocket 传输**（`coder/websocket`）：单端点 `/api/ops/ws`，首帧声明会话类型；服务端会话注册表支持断线重连并重放回滚缓冲。
- **会话管理**：并发上限、空闲回收、256KB 环形回滚缓冲、输出截断标记。
- **跨平台隔离**：`pty_unix.go` / `pty_windows.go` 通过构建标签拆分，Windows 下 `go build` 与 `go test` 均通过，前端自动隐藏终端入口。

### 安全模型（本功能风险等级最高）

- **双重前置 fail-closed**：必须 `ops.enabled: true` **且** `ops.token` 非空，面板才被注册。仅开 enabled 而未设 token 时保持禁用并输出告警。
- **面板独立口令**：`ops.token` 与 `server.token` 解耦——浏览保持简单，面板凭据可单独轮换/吊销。ops 路由跳过全局鉴权中间件，由面板自行校验。
- **独立第二因子**：`ops.terminalToken` 专用于交互式终端，与全局 token 解耦（沿用 `manage.deleteToken` 的模式）。
- **WebSocket Origin 校验**（**唯一防线**）：会话 Cookie 为 `SameSite=Lax`，而 Lax 不阻止跨站 WebSocket 握手。若不校验 Origin，任何被访问的恶意网页都能静默连接内网面板获得 root shell（CSWSH）。因此强制校验 Origin 白名单，并要求握手**显式携带 token**（URL 参数或 Bearer 头），**不接受仅靠 Cookie 隐式通过**。
- **拼接符扫描先于白名单匹配**：元字符（`;` `&&` `||` `|` `` ` `` `$(` `>` `<` `&` 及换行）在归一化**之前**对原始字符串扫描——归一化会把换行折叠为空格，导致 `ls\nrm -rf /` 伪装成无害命令。含拼接符者直接拒绝，不进入正则匹配。
- **提权前缀剥离**：`sudo`/`doas`/`pkexec`/`nohup` 等前缀在 deny 匹配前剥离，防止 `sudo rm -rf /` 绕过锚定规则（`^\s*rm\b`）。
- **deny 规则锚定到命令位置**：避免把路径参数误伤——未锚定的 `\bmv\b` 会拒绝 `ls /data/mvtest`，`\bmount\b` 会拒绝 `cat /etc/mount.conf`。锚定后规则针对「执行该命令」而非「提及该名称」。
- **环境变量白名单透传**：子进程仅继承 `PATH`/`HOME`/`LANG`/`LC_ALL`/`TERM`/`USER`/`SHELL`/`TMPDIR`，**绝不继承服务进程完整 env**——否则一条 `env` 即可读走 `server.token`、`manage.deleteToken` 等全部凭据。
- **进程组回收**：Unix 下 `Setpgid` + 向进程组发信号，超时 SIGTERM → 3s 宽限 → SIGKILL，防止管道子进程成为孤儿。
- **cwd 沙箱**：工作目录限制在 `roots`（或 `ops.cwdRoots`）内，含软链接解析。文档明确其**不是安全边界**（仅约束工作目录，不阻止读取沙箱外文件）。
- **审计日志**：每次执行（含被拒绝的）记录客户端 IP、cwd、命令、退出码、耗时、是否截断，走既有 `log` 模块。

### 内置只读命令白名单

按「开箱即用 + 默认安全」原则，内置一份只读命令白名单（`ls`/`cat`/`head`/`tail`/`wc`/`stat`/`file`/`du`/`df`/`tree`/`grep`/`rg`/`find`/`ps`/`uptime`/`free`/`uname`/`hostname`/`whoami`/`id`/`date`/`env`/`ss`/`netstat`/`ip`/`systemctl status|is-active|list-units`/`journalctl`/`docker ps|logs|images|inspect`/`git status|log|diff|show|branch`）。

- `ops.allow` 为**追加**语义，非替换；
- 分页器与交互式工具（`less`/`more`/`top`/`vi`）**故意排除**（会阻塞等待输入，属终端模式场景）；
- 内置 deny 危险规则集（`rm`/`mkfs`/`dd`/`chmod`/`chown`/`mount`/`useradd`/`passwd`/`shutdown`/`iptables`/`crontab`/包管理器/裸设备写入等），写 `deny: []` 才清除。

### 前端：独立资产 + 运行时隔离

- **独立目录 `web/static/ops/`**：`ops.js`（Alpine 组件）、`ops.css`、`ops.html`（独立页）。
- **DOM 运行时自建**：`index.html` 仅含一个空挂载点 `<div id="ops-panel-root">`，抽屉结构由 `ops.js` 运行时注入；工具栏按钮同样由 JS 动态查找 `.toolbar-left` 后追加，主站模板不含任何 ops 结构。
- **独立 Alpine 组件**：`ops.js` 自行注册 `Alpine.data('opsPanel', ...)`，不修改 `app.js`，两者零符号依赖。
- **事件总线解耦 cwd 跟随**：`app.js` 仅新增 **1 行** 广播 `window.dispatchEvent(new CustomEvent('filelist:navigate', {detail:{path}}))`；`ops.js` 订阅该事件。主站只广播不知谁在听，ops 未启用时零开销。契约仅两个符号（事件名 + `detail.path`）。
- **配置经占位符注入**：新增 `__FILELIST_OPS__` 占位符；`ops.terminalToken` **绝不下发前端**，前端仅得知「是否需要口令」。
- **交互功能**：cwd 自动跟随（可 🔒 锁定）、按 cwd 分组存 localStorage 的命令历史（↑↓ 翻页）、退出码与耗时展示、输出截断提示、断线自动重连并重放、终端尺寸自适应（防抖）、暗色模式适配、弹出独立窗口。

### 已知边界

- Windows 平台无交互终端（`creack/pty` 为 Unix 专用），仅提供一次性命令模式。
- `ops.mode: free` 下仅内置 deny 规则约束，爆炸半径显著增大，启动时会输出高风险告警。
- 反代场景需显式配置 `ops.originPatterns`，否则 Origin 与 Host 不匹配将导致握手被拒。
