> 创建时间：2026-09-16 09:45 (GMT+8)  
> 状态：方案设计完成，待审批实施

---

## 一、 项目背景与设计目标

### 1.1 背景
当前 `filelist` 系统已具备文本文件基础查看与编辑功能（基于 `textModal` 弹窗与文本框），能够满足通用代码和配置文件的简短浏览与修改。然而，对于长篇网络小说、电子书（通常单文件在 2MB～10MB+，字数在 100万～300万字以上）的阅读场景，通用文本框存在以下核心痛点：
- **性能瓶颈**：超大文本一次性渲染进 DOM 会导致页面卡死、内存暴增、排版崩溃；
- **排版缺失**：缺乏字号、行高、段落缩进、夜间/护眼配色、居中版心等专业小说排版能力；
- **编码乱码**：中文网络小说有极大比例采用 `GBK / GB18030` 编码，通用 UTF-8 请求会产生大量乱码；
- **进度丢失**：缺乏章节识别与阅读进度（百分比/章节/段落）的精确记忆与跨会话自动恢复；
- **沉浸感差**：缺乏全屏沉浸、目录检索抽屉、快捷键翻页、隐藏控制条等专业阅读器体验。

### 1.2 设计目标
1. **纯前端独立解耦**：作为独立单页面运行（`reader.html`），通过 URL 参数（`?url=...&title=...`）接收目标文件，与主站主逻辑完全解耦；
2. **双模式兼容**：既支持加载服务端 `/raw/...` 直链，也支持本地拖拽/选取本地 `.txt` 离线即开即读（用于本地验证与离线阅读）；
3. **高可维护性与扩展性**：复用主站已内置的轻量响应式框架 `alpine.min.js`，状态清晰、模块解耦、易于维护和后续扩展插件（如朗读 TTS、书签批注等）；
4. **极致性能**：实测支持数百万字超大文本，秒级解码分章，DOM 恒定轻量按需渲染，零卡顿；
5. **智能自适应编码**：原生双阶嗅探解码（UTF-8 异常自动降级 GB18030，提供手动兜底切换），杜绝乱码；
6. **人性化阅读体验**：4套经典阅读主题、自由定制字号/行距/版宽、智能目录识别与搜索、键盘与手势翻页、两级进度持久化。

## 二、 技术选型与可维护性设计

为兼顾**开发与维护效率**、**轻量级零构建负担**和**长期可扩展性**，技术选型如下：

| 模块 | 选型 | 选用理由与可维护性评估 |
| :--- | :--- | :--- |
| **UI 与状态驱动** | **Alpine.js (`alpine.min.js`)** | 复用主站已有资源（~44KB，零额外网络请求）。相比散落的 Vanilla JS DOM 拼接，Alpine.js 提供清晰的响应式数据模型（`x-data`）、声明式事件与指令绑定（`x-show`, `x-on`, `x-model`），使设置抽屉、目录筛选、主题切换等复杂状态条理分明，未来扩展书签、笔记、TTS 朗读时无需重构 DOM 逻辑。 |
| **排版与样式系统** | **专属现代 CSS 变量体系** | 针对小说阅读专门编写轻量 CSS（~400 行），定义系统级 CSS Variables（`--reader-bg`, `--reader-text`, `--reader-font-size`, `--reader-max-width` 等）。彻底解耦 Pico CSS 对通用表单和表格的默认干预，保证阅读界面的极致纯粹。 |
| **字符解码引擎** | **原生 `TextDecoder` 双阶探测** | 利用现代浏览器标准 `TextDecoder` 原生 C++ 级别速度，不引入第三方笨重探测库。首选 `utf-8 { fatal: true }`，遇非法字节立即捕获并降级到 `gb18030`，兼容 100% 中文小说。 |
| **图标体系** | **内联轻量 SVG 图标集** | 零外部字体/网络依赖，纯矢量高清晰度，随页面即时渲染，避免网络加载闪烁。 |

### 3.1 编码嗅探与大文本加载引擎
1. **获取原始数据**：
   - 远程：`const buf = await (await fetch(url)).arrayBuffer();`
   - 本地：`const buf = await file.arrayBuffer();`
2. **零依赖安全解码器**：
   ```javascript
   function decodeNovelBuffer(buffer) {
     try {
       // 优先使用严格模式检测 UTF-8
       const utf8 = new TextDecoder('utf-8', { fatal: true });
       return { text: utf8.decode(buffer), encoding: 'utf-8' };
     } catch (e) {
       // 触发非法字符序列时无缝降级为 GB18030 (兼容 GBK, GB2312)
       const gbk = new TextDecoder('gb18030');
       return { text: gbk.decode(buffer), encoding: 'gb18030' };
     }
   }
   ```
3. **文本排版净化**：
   - 将 Windows 风格 `\r\n` 规范化为 `\n`；
   - 将多于 2 行的连续空白空行压缩为单行空行；
   - 清除行首杂乱空格，为正文段落统一设置 `text-indent: 2em`。

### 3.2 智能章节解析与索引目录（TOC Engine）
1. **章节正则表达式**：
   基于对真实海量小说的实测统计（覆盖卷、章、回、节、部、序、外传等）：
   ```javascript
   const CHAPTER_REGEX = /^[ \t\u3000]*(第[0-9零一二两三四五六七八九十百千万]+[章回节卷集幕篇部话]|Chapter\s+\d+|序[言章]|前言|后记|楔子|尾声|番外)[ \t\u3000]*(.*)$/gm;
   ```
2. **轻量化目录索引构建**：
   - 扫描全文，仅记录章节标题及对应的正文切片偏移量 `{ id, title, start, end }`；
   - 内存仅常驻原始文本字符串一份，目录对象体积在几百 KB 以内；
   - 若全文未匹配到有效章节（如散文、短篇或格式特殊），自动按每 5,000 字生成逻辑分页，保证分页体系的完备性。

### 3.3 章节级按需渲染（彻底杜绝卡顿）
- **按章切片渲染**：页面 DOM 中只挂载当前章节的段落（通常几十个 `<p>` 标签）。
- **极低内存消耗**：即使小说高达 3,000 万字，浏览体验与阅读几千字短文完全无异。
- **跨章无感过渡**：
  - 滚动模式：滑到本章末尾时显示【进入下一章：XXX】提示按钮，或可配置为连续流式拼接下一章；
  - 翻页模式：提供上一章 / 下一章平滑切换动画。

### 3.4 精确双级阅读定位（localStorage 记忆恢复）
1. **存储键值命名规范**：
   `reader_pos_${md5/base64(fileUrl || fileName + fileSize)}`
2. **数据持久化模型**：
   ```json
   {
     "url": "/raw/novel.txt",
     "title": "大秦皇陵.txt",
     "chapterIndex": 12,
     "chapterTitle": "第十三章 诡异祭坛",
     "scrollRatio": 0.45,
     "totalPercent": "18.6%",
     "updatedAt": 1726451200000
   }
   ```
3. **定位恢复算法**：
   - 页面启动时读取 `chapterIndex`，优先挂载目标章节；
   - 监听图片/DOM 布局就绪后，按 `scrollRatio` 计算目标 `scrollTop` 进行平滑复位；
   - 当用户调整字号、切换全屏或改变视口宽度时，重算保持段落比例相对静止，避免飞页错位。

### 3.5 排版与阅读视觉系统
1. **主题配色系统（4套精选预设）**：
   - **羊皮纸/复古（Paper，默认推荐）**：背景 `#f4edd9`，文字 `#382e2b`，柔和舒适，仿真纸张；
   - **豆沙绿/护眼（Green）**：背景 `#e1ece1`，文字 `#243825`，长久阅读防眼疲劳；
   - **深邃黑/夜间（Dark）**：背景 `#1a1a1c`，文字 `#9e9ea3`，暗光环境防刺眼；
   - **日间白/典雅（Light）**：背景 `#ffffff`，文字 `#222222`，高对比清晰。
2. **个性化调节**：
   - **字体大小**：14px ～ 32px，步进 2px；
   - **行高间距**：1.4 ～ 2.4；
   - **正文字体**：系统默认无衬线、中文宋体/明朝、黑体、楷体；
   - **版心宽度**：紧凑（650px）、标准（800px）、宽阔（1000px）、全宽（100%）；
   - **持久化**：用户个性化排版偏好自动保存在 `localStorage['reader_preferences']`，跨书籍通用。

### 3.6 交互系统与沉浸控制
1. **热区点击交互**：
   - **屏幕中央区域（30% ~ 70%）**：点击平滑呼出 / 隐藏顶部控制栏、底部进度条；
   - **屏幕左侧区域（< 30%）**：翻向上一页 / 滚动向上；
   - **屏幕右侧区域（> 70%）**：翻向下一页 / 滚动向下。
2. **桌面全键盘快捷键支持**：
   - `Space` / `PageDown` / `→` / `↓`：向下滚动或下一页；
   - `PageUp` / `←` / `↑`：向上滚动或上一页；
   - `[` / `]`：快速切换上一章 / 下一章；
   - `T`：打开 / 收起章节目录抽屉；
   - `F`：一键进入 / 退出沉浸全屏；
   - `Esc`：关闭打开的弹窗或抽屉。
3. **目录抽屉（TOC Drawer）**：
   - 左侧滑出抽屉，包含即时搜索框（支持首字母、关键词过滤上千章节）；
   - 高亮当前阅读中的章节，一键点击瞬时跳转。
4. **常驻微型状态栏**：
   - 沉浸阅读时在页面底部保留微透弱化状态行：当前章节名称、全书已读百分比、当前系统时间。

## 四、 与当前系统（filelist）的集成方案

### 4.1 服务端（Go）支持
- 无需对后端做侵入式修改：
  - 阅读器页面放置在 `src/web/static/reader.html`；
  - `src/server.go` 已内置 `static/` 静态文件服务（`webFS` 内嵌），启动后可直接访问：
    `http://host:port/static/reader.html?url=...`；
  - 增强便利性（可选）：可在 `src/server.go` 增加 `/reader` 友好别名映射。

### 4.2 Web 前端入口打通
1. **文件列表与网格卡片操作**：
   - 针对扩展名为 `.txt` 的文件，在操作栏提供「📖 阅读」按钮；
   - 点击调用 `window.open(base + '/static/reader.html?url=' + encodeURIComponent(rawUrl) + '&title=' + encodeURIComponent(item.name), '_blank')`，在新标签页独立开启。
2. **文本查看/编辑弹窗（`textModal`）顶栏集成**：
   - 在现有的「保存」、「下载」按钮旁，增添「📖 阅读模式」快捷图标，方便用户在普通预览时一键切换至小说沉浸式阅读。

## 五、 测试与验证规划

### 5.1 真实样本验证集
使用本地真实小说样本库（`E:\Books\精校小说`），覆盖以下典型场景：
1. **超大容量与高章节数**：
   - 如《唐朝好医生》（6.45MB，326万字，912章）；
   - 如《九星天辰诀》（6.52MB，315万字，1514章）。
2. **字符编码覆盖**：
   - 验证 `GB18030` 编码小说能否 100% 自动识别，无任何问号或乱码；
   - 验证 `UTF-8` 编码小说自适应加载；
   - 验证异常情况下手动切换编码功能。
3. **章节标题匹配准确性**：
   - 验证中文字符（第X章）、阿拉伯数字（第001章）、序章、前言、番外等正则提取覆盖率。
4. **本地文件拖拽直接测试**：
   - 打开 `reader.html`，将 `E:\Books\精校小说` 中的 txt 文件拖入窗口，验证本地加载和渲染流畅度。
5. **记忆持久化测试**：
   - 阅读到指定章节并滚动到中段后刷新页面，验证是否精准复位。

## 六、 分步实施路线图

1. **步骤 1：编写独立阅读器页面（`src/web/static/reader.html`）**
   - 搭建纯前端单页面骨架，引入复用 `src/web/static/alpine.min.js`；
   - 实现原生 `TextDecoder` 双阶编码自适应探测与加载流；
   - 实现本地文件拖拽与文件选择器（用于无参启动和即时测试）；
   - 实现正则智能分章索引算法。
2. **步骤 2：沉浸式阅读核心 UI 与交互开发**
   - 编写专业现代小说排版样式（4套主题、字号行距宽度变量系统）；
   - 实现正文按需分章渲染与上下章切换；
   - 实现左侧目录抽屉与快速过滤搜索；
   - 实现 `localStorage` 两级位置记忆与自动复位；
   - 实现热区点击隐藏/显示菜单、全屏模式与键盘快捷键绑定。
3. **步骤 3：真实小说样本测试与调优**
   - 使用 `E:\Books\精校小说` 的多部百万字小说进行全功能性能压测与排版核对；
   - 优化正则容错率与内存表现。
4. **步骤 4：主系统（filelist）无缝集成与回归测试**
   - 在列表和 `textModal` 弹窗中注入一键阅读入口；
   - 编译 Go 二进制并执行 E2E 与人工全流程回归验收。
