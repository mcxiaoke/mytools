# 变更记录 2026-10-31

## [2026-10-31 09:57:32] 修复拖动上传触发双重事件导致同名文件重复生成 (1) 副本的问题

### 背景与问题根因
- **问题现象**：用户在网页中拖拽上传多个文件（如 3 个分卷压缩包 `PrivateData-v4-20261031.part1.rar` ~ `part3.rar`）后，页面刷新出两组完全重复的文件，其中一组文件名被自动加上了 `(1)` 后缀（如 `part1.rar` 与 `part1 (1).rar` 并存）。
- **根因分析**：
  1. **双重事件监听**：在 WebUI 重构过程中，`src/web/static/app.js` 的 `initDragAndDrop()` 中已在全局 `window` 上绑定了统一的 `drop` 监听器，用于支持全窗口拖拽上传；但同时 `src/web/index.html` 中的容器元素 `<div id="tableWrap">` 仍然保留了遗留的 `@drop.prevent="handleDrop($event)"` 指令；
  2. **事件冒泡未截断**：当用户将文件拖拽并释放在网页文件列表区域（`#tableWrap` 或其内部行元素）时，先触发了 `#tableWrap` 上的 `@drop.prevent`，调用了 `handleDrop` 发起第一次上传；而 Alpine 的 `.prevent` 修饰符仅调用了 `preventDefault()`，未调用 `stopPropagation()`；该原生 DOM drop 事件继续冒泡至 `window`，触发了 `window` 上的 `drop` 监听器，再次调用 `uploadFiles` 发起了第二次并发上传；
  3. **同名冲突防覆盖机制**：由于同一个拖拽动作在同一毫秒内并发向后端 `/api/upload` 发送了两个完全相同的上传请求，第一个请求成功保存了原文件名文件；第二个请求到达时检测到同名文件已存在，后端的同名防覆盖算法（`availableFilename`）自动为第二批文件追加了数字编号 `(1)`，最终导致目录中生成了一组原文件与一组带 `(1)` 的冗余副本。
  4. **并发重入缺乏守卫**：`uploadFiles(files)` 方法缺少上传中的互斥状态检查（`this.uploading`），当连续或并发触发上传调用时未作任何拦截。

### 修复与优化措施
1. **统一单点拖拽监听，消除事件冒泡**（`src/web/index.html`）：
   - 移除 `#tableWrap` 容器上冗余的 `@dragover.prevent`、`@dragleave.prevent` 和 `@drop.prevent="handleDrop($event)"`，仅保留状态绑定 `:class="{ 'drop-active': isDragOver }"`；
   - 拖拽与放置事件全生命周期统一由 `window` 监听器集中处理，无论拖放至页面何处均只触发一次上传，彻底消除容器与窗口双重触发问题。
2. **防重入与防御性加固**（`src/web/static/app.js`）：
   - 在 `uploadFiles(files)` 入口处增加 `if (this.uploading) return;` 状态互斥锁，并在界面提示已有上传进行中，杜绝并发重入上传；
   - 在 `handleDrop(e)` 中增加 `e.stopPropagation()` 防冒泡防御，并在全局 `window` 监听器中补齐 `dragend` 事件自动复位 `isDragOver = false`。
3. **端到端测试覆盖**（`tests/e2e/specs/upload.spec.js`）：
   - 新增 E2E 测试用例 `should not duplicate files when dropping multiple files onto tableWrap element`，模拟直接向 `#tableWrap` DOM 容器抛出多文件拖放事件，断言所有文件正常上传且绝不包含 `(1)` 冲突副本，每个文件在列表中严格仅出现 1 次。
