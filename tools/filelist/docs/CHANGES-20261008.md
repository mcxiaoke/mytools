## 14:53:28 — 全量替换主索引引擎为紧凑索引 (CompactIndex + FLIX Raw) 并简化持久化配置

- 背景与目标：根据实测性能与评审结论，将 FileList 主索引引擎全面切换为无指针连续切片紧凑索引（`CompactIndex`），移除旧版 GOB 与 `map[string]Entry`，实现百毫秒级持久化、零锁并发检索以及常驻内存下降 90% 的目标；同时将索引扩展名变更为 `.db` 并精简配置。
- 核心替换与实现：
  - `src/indexer.go`：
    - 彻底移除旧版 `entries map[string]Entry`、`dirStamp`、`gen` 以及 GOB 序列化逻辑；
    - 引入 `atomic.Pointer[CompactIndex]`，对外搜索 `Search()` 实现绝对零锁并发读；
    - `BuildIndex()` 与后台扫描全面接入 `buildCompactPass`，原子更新指针；
    - 对齐 `save()` / `load()` 对接 FLIX Raw 格式持久化。
  - `src/indexer_compact.go`：
    - 实现紧凑索引深度优先构建器 `buildCompactPass` 与子树极速复制 `copySubtree`（增量跳过未变目录磁盘 I/O）；
    - 实现目录内子文件二分排序与文件级精准 Diff（准确统计 `Added`、`Changed`、`Removed`、`Skipped`）；
    - 实现 `TotalEntries()`（排查虚拟根节点）与 `AllEntries()`；
    - `Save()` 与 `LoadCompactIndex()` 引入 `bufio` 缓冲，Raw 模式 245 万条目序列化 140ms、反序列化 106ms。
- 持久化规范与配置精简：
  - `src/config.go`、`config.sample.yaml`、`src/main.go`：
    - 移除配置项 `index.persist`，索引数据库统一存放在 `dataDir` 下（默认 `dataDir/filelist.db`），由 `(*Config).IndexPath()` 统一管理；
    - `c.DataDir == ""` 时 `IndexPath()` 返回空字符串，防止无显式数据目录的临时单测向工作目录生成残留文件。
    - 索引扩展名变更为 `.db`，避免原 `.idx` 在 Windows 或播放器中被识别为字幕文件。
  - `.gitignore`：追加 `*.db` 规则。
- 测试验证与文档：
  - `src/indexer_test.go` & `src/indexer_compact_test.go`：全量单测适配并通过（包括 245 万条目全量比对与往返校验）；
  - `docs/DESIGN-COMPACT-INDEX-20261008.md`：升级至 v3，全面同步最新代码实现、数据结构与基准对比结果。

## 14:20:00 — 紧凑索引架构 (CompactIndex) 独立实现与实测对比评估

- 背景：根据评审意见 `docs/REVIEW-COMPACT-INDEX-20261008.md` 完善架构设计文档 v2，独立实现无指针连续切片紧凑索引原型与真实数据对比基准测试。
- 设计更新：
  - 更新 `docs/DESIGN-COMPACT-INDEX-20261008.md` 至 v2：确立 Folder/File 双连续切片拓扑、Arena 零拷贝字节流扫描、按目录二分增量 Diff、原子不可变快照读写分离，以及 Little-Endian 二进制 FLIX v3 规范。
- 核心实现：
  - `src/indexer_compact.go`：
    - `CompactFolder` (40B, noscan) 与 `CompactFile` (32B, noscan) 纯值类型切片定义；
    - `StringArena`：单块字节池存储短名称与虚拟路径；
    - `Search()`：直接基于 Arena 字节流做 ASCII 折叠与大小写敏感扫描，过滤阶段零堆分配，仅对 Top-N（如前50条）延迟物化 `Entry`；
    - `Save()` / `LoadCompactIndex()`：带 `bufio` 缓冲的二进制 FLIX 格式持久化，支持 Raw 与 Gzip 双模式并带 CRC32 完整性校验；
    - `BuildCompactIndexFromEntries()`：从既有条目构建紧凑拓扑与目录内文件名二分排序。
  - `src/indexer_compact_test.go`：
    - 验证路径重建、目录内文件二分查找、FLIX 序列化往返校验；
    - 验证 `CompactIndex.Search` 与既有 `Indexer.Search` 搜索结果、排序与评分 100% 等价性；
    - 基准测试 `TestBenchmarkRealComparison`：加载真实运行产生的 245.4 万条目 `filelist.idx` 进行端到端实测。
- 实测对比结论（基于真实 2,454,659 条目数据集）：
  - 常驻内存（HeapAlloc）：旧版 GOB 1,224 MB -> 新版 CompactIndex 229 MB（**降低 81.3%**）；
  - 磁盘文件大小：旧版 GOB 608.05 MB -> 新版 FLIX Raw 154.93 MB（**缩减 74.5%**），FLIX Gzip 44.77 MB（**缩减 92.6%**）；
  - 磁盘加载耗时：旧版 GOB 2.08s -> 新版 FLIX Raw 106ms（**快 19.6 倍**），FLIX Gzip 725ms（**快 2.9 倍**）；
  - 全量 245 万条搜索延迟：零分配字节流扫描平均耗时 98ms ~ 191ms，扫描过程 GC 堆分配为 0。

## 13:49:07 — 内置常见开发环境排除清单与配置合并机制

- 背景与原因：生产环境挂载大盘时，`msys64`、`Scoop`、`flutter`、`android-sdk`、`venv` 等开发环境与依赖缓存产生超过 150 万个碎片文件，导致索引内存膨胀至 4~5GB。原 `defaultExcludeDirs` 仅包含 5 个基础目录，且若用户配置了 `excludeDirs` 会导致默认排除被完全覆盖失效。
- `src/config.go`：
  - 新增 `BuiltinExcludeDirs`：内置常见开发环境、包管理、工具链、构建输出和 IDE 缓存目录清单（版本控制 `.git`/`.svn`/`.hg`；前端 `node_modules`/`.pnpm-store`/`.yarn`；Python `venv`/`.venv` 等；Java/Kotlin `.gradle`/`.m2`；Rust/Go `target`/`vendor`；移动端与 SDK `flutter`/`android-sdk`/`.dart_tool`/`Pods` 等；Windows 工具链 `msys64`/`msys32`/`cygwin`/`cygwin64`/`w64devkit`/`Scoop`/`ScoopApps`；构建产物 `bin`/`obj`/`.vs`/`.idea`/`.vscode` 等；系统卷 `$RECYCLE.BIN`/`System Volume Information`）。
  - `defaultExcludeDirs` 指向 `BuiltinExcludeDirs`，保持向后兼容。
  - 新增 `index.builtinExcludes` 开关配置项（默认 `true`）及 `BuiltinExcludesEnabled()` 辅助方法。
  - 新增 `mergeUniqueDirs`：大小写不敏感去重合并基础排除项与用户自定义排除项。
  - `LoadConfig()`：启用 `builtinExcludes` 时，自动将 `BuiltinExcludeDirs` 与用户自定义 `excludeDirs` 合并生效（不再粗暴覆盖），确保用户即使仅配了自定义项也能享有内置防护；显式配置 `builtinExcludes: false` 时允许完全退出内置名单。
- `src/main.go` & `config.sample.yaml`：
  - 更新默认配置文件生成模板与示例配置文件，增加 `builtinExcludes: true` 说明及排除目录合并注释。
