## 15:40:00 — 修复深层变更漏索引：rescanDepth 强制走查 + fullInterval 定期全量

- 修复的 bug：增量索引以根目录 `(mtime,size)` 指纹决定是否整树跳过，而深层新增/变更不会更新根目录 mtime，导致整棵树被跳过、变更永远进不了索引（重启也无效，因为重启加载持久化索引后仍走同样的增量跳过逻辑）。
- `src/config.go`：
  - `index.rescanDepth`（默认 3）：每轮增量 pass 无条件走查每个 root 的前 N 层；第 N 层以下的目录维持"指纹未变则跳过"。`<=0` 时回落为默认值。
  - `index.fullInterval`（默认 `24h`，`0s` 关闭）：距上次全量构建超过该时长后，下一次 pass 强制全量重建（不做任何指纹跳过），作为深层盲区的兜底。
- `src/indexer.go`：
  - `BuildIndex(forceFull bool)`：`forceFull` 或间隔到期时禁用增量；全量构建完成时刷新 `lastFull`。新增 `fullDue()`。
  - `scan()` 根目录仅在 `rescanDepth<=0` 时允许整树跳过；`walkRoot()` 子树跳过条件增加 `depth+1 >= rescanDepth`。
  - `NewIndexer()` 解析 `fullInterval`；加载持久化索引成功后用持久化文件 mtime 近似 `lastFull`（偏保守：只会推迟、不会漏掉全量）。
- `src/main.go`：启动横幅 Index 行追加 `rescanDepth`/`fullInterval`；默认生成配置模板同步。
- 测试：`TestBuildIndex_RescanDepthDetectsDeepChanges`（深层加文件、根 mtime 不变仍被检出 + 强制走查不产生幽灵增删）、`TestBuildIndex_ForceFullDropsStaleEntries`（强制全量 GC 未见条目、lastFull 刷新、fullDue 翻转）；`TestLoadConfig_Defaults` 补默认值断言；现有 `BuildIndex()` 调用点（indexer_test/server_test）更新为 `BuildIndex(false)`。
- 性能依据（C:\Home 实测，38.7 万目录/209 万文件）：前 3 层走查 89ms/pass、前 4 层 0.46s，全量冷 2m5s/热 67s——rescanDepth=3 成本可忽略，全量按天一次可接受。
- 验证：`go vet`/`go test`（含 `-count=3` 稳定性）通过；E2E 46/46 通过；真实进程复现场景验证——停服后深层加文件、重启进程，新文件立即出现在 `/api/search` 结果中。

## 14:56:08 — 搜索性能：排序缓存 + 请求竞态保护 + 防抖 600ms

- `src/web/static/app.js`：
  - `sortedItems` 由 getter 改为缓存属性：原先每个模板绑定各自触发一次 slice+排序（自然排序 collation 开销大，500 条 × 5~6 处引用/每次更新），现在仅在 `items`/`sortCol`/`sortDir` 变化时经 `resort()` 重算一次。
  - 请求竞态保护：`loadDir`/`doSearch` 各带自增序号（`loadSeq`/`searchSeq`），过期响应直接丢弃，只采纳最后一次结果；快速输入+回退时不再出现旧结果覆盖新结果。
  - `navigate` 重置排序后同步调用 `resort()`，避免导航加载期间残留旧排序。
- `src/web/index.html`：搜索输入防抖 300ms → 600ms。
- 验证：全量 E2E 46/46 通过（含 search/sorting/grid/upload/manage）。

## 14:26:23 — 索引扫描进度日志 + 重复 root URL 校验

- `src/indexer.go`：
  - 新增 `scanProgress` 结构与 `scanProgressInterval`（10s）常量；`walkRoot` 每读完一个目录累计计数，超过间隔输出一条进度日志（已扫描条目数、目录数、当前目录、耗时）。
