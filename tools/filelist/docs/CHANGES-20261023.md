# 变更记录 2026-10-23

## [2026-10-23 11:08:38] 修复移动端列表视图文件名显示不全与操作列空白挤压问题

### 背景与问题根因
- **问题现象**：在手机移动端竖屏（视口宽度 $\le$ 640px）下，列表视图中超过 4~5 个字符的文件名和目录名即被省略截断为 `ai-s...`、`and...`、`De...`，而右侧操作按钮与名称之间存在大量突兀的空白区域（占屏幕宽度的 65%~80%）。
- **根因分析**：
  1. 在移动端媒体查询（`@media (max-width: 640px)`）中，`size` 与 `time` 列被隐藏，表格只剩 `name` 与 `actions` 两列；
  2. 样式原先将 `th.name-col` 与 `th.actions-col, td.actions` 同时声明为 `width: auto`；
  3. 由于 `td.name` 设置了 `max-width: 0`（用于实现文本单行省略截断），在 Chromium/Blink 的表格自动排版算法中，`name` 列的内在期望宽度被判定为极小值；
  4. 浏览器将表格总宽度中所有的多余空间全部分配给了没有 `max-width` 限制的 `actions` 列，使操作列占用了 230px+ 的宽度，而 `name` 列被压榨到仅剩 40~79px 可用文字宽度。

### 修复与优化措施
1. **移动端表格列宽权重修复**（`src/web/static/app.css`）：
   - 将 `th.name-col` 设为 `width: 100%`，确保名称列独占所有剩余可用空间；
   - 将 `th.actions-col, td.actions` 设为 `width: 1%; white-space: nowrap; text-align: right;`，使其紧凑收缩到恰好包裹操作按钮的最小内容宽度（~100px），多一分不占；
   - 在 400px 移动视口下，名称列可用宽度从原来的 79px 扩增至 250px+（在仅有目录时可达 330px+），普通目录和文件名完全展开显示，超长文件名平滑截断，无横向溢出。
2. **文件名完整标题提示**（`src/web/index.html`）：
   - 为列表视图的 `td.name a` 添加 `:title="item.name"`，支持桌面端鼠标悬停与移动端长按弹出原生系统 Tooltip 查看完整文件名。
3. **测试加固**（`tests/e2e/specs/navigation.spec.js`）：
   - 在移动端视口（400x840）用例中追加断言：验证名称链接具备 `:title` 属性，且 `td.name` 宽度 > 250px，`td.actions` 宽度紧凑（< 120px），防止该布局退化问题重现。
