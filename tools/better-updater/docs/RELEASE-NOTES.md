## 1.1 承诺范围收缩（2026-09-16，**集成方必须重读**）

原表述"任意时刻被强杀/终止/掉电均可确定性收敛"是**过强承诺**，已修正为：

| 层 | 场景 | 是否承诺 |
| :--- | :--- | :--- |
| L1 | 进程内失败 | ✅ 整包回滚（退出 1） |
| L2 | 施工进程被杀，看门狗存活 | ✅ 看门狗接管并收敛（**覆盖杀软清理 / `taskkill` / 启动器清进程树等常见情况**） |
| L3 | 看门狗亦亡（掉电 / 重启） | ⚠️ **尽力而为，不作承诺** |

**为什么**：L3 要"下次有 `updater.exe` 被启动"才会发生，而触发者只有调用方；
更关键的是，被中断的更新可能让**启动闭包**（入口 exe 及其 loader 期依赖）半新半旧，
应用**在 `main()` 之前就失败**，调用方的启动自检代码根本执行不到。

**取代它的两条路径**（都不依赖宿主能否启动）：

1. `updater.exe` **无参数**运行 = 收敛自身所在目录（`USAGE.md` §12）——安装目录里双击即可；
2. **保留更新包**，必要时解压覆盖（`USAGE.md` §13）——附 `.updatekeep` 前提。

**原"必须同步执行 `--recover`"的硬性契约已降为可选加固**，集成契约由 8 项变为 7 项。

## 2. 新增能力

| 能力 | 说明 |
| :--- | :--- |
| **崩溃自愈（三层）** | L1 进程内回滚 / L2 看门狗接管 / L3 冷启动按 Journal 收敛。任意时刻被强杀、终止、掉电后确定性收敛 —— **已通过真实进程终止验证**（非模拟） |
| **版本与降级防护** | 读 `updater.manifest` + `.updater\state`；版本更低默认拒绝（`--allow-downgrade` 放行）；跨度过大由 `MIN_UPGRADABLE_FROM` 拒绝 |
| **离线版本回退** | `--rollback-previous`：用本地保留的上一版本原地回退，无需网络、秒级完成；回退本身也是事务，**可再回退** |
| **保留上一版本** | `previous\<GEN>\` + `_meta.txt`，默认保留 7 天（`--previous-ttl-days`） |
| **提交前逐文件哈希自检** | 包内含清单时，提交前重新读盘比对 size + SHA-256；不符则整包回滚。**流式实现，内存与文件体积无关** |
| **自动更新自身** | `updater.exe` 位于安装目录内时，通过影子 Worker 接棒，使 `target\updater.exe` 可随包更新（旧版只能无条件跳过自己） |
| **占用者诊断** | 遇文件占用时用 Restart Manager **只读**列出占用者进程与 PID 写入日志（**不关闭任何进程**） |
| **进度可见** | `--progress-file` 输出阶段与百分比，供宿主轮询显示 |
| **原生进度窗** | `--gui` / `--gui-title`：跑马灯 → 平滑百分比，中英文自适应，独立 UI 线程防假死。未传 `--gui-title` 时标题自动带应用标识（`<--launch 入口名> - 正在更新...`） |
| **单句柄锁定** | 预检与事务锁定同一文件对象（`FILE_SHARE_READ`），从根上消灭"验签对象 ≠ 解压对象" |
| **包防护加强** | 压缩方法约束（仅 Store/Deflate）、加密条目拒绝、大小写不敏感重复条目拒绝、Zip Slip、zip bomb 双层、Junction 越界识破 |
| **跨会话并发锁** | `.updater\lock` 文件独占锁（旧版为按会话隔离的命名互斥量），并带 10s 容差轮询 |
| **运维排障** | `--recover`、`--debug-console`、`--strict-path-check`、`--skip-hash-verify`、结构化 `END:` 日志行；等待 `--pid` 超时时给出"宿主是否同步等待了退出码"的 `hint:`；从终端直启 release 产物时 `--help` / `--version` / `--dry-run` 与参数错误**自动附加父控制台**（被重定向时语义不变） |
| **打包工具（开发期）** | `packer`（`cargo run --release --features pack --bin packer -- --stage … --version … --out …`）：清单 → 压缩（启动闭包连续收尾）→ 回读自检 → 输出 sha256。**不依赖 PowerShell**，任意语言的 CI 都能调；**不进更新器发布产物**（`updater.exe` 大小与行为完全不受影响）。`-V` / `--build-info` 打印它自身的构建身份 |
| **构建身份（可追溯）** | `updater.exe --version` 在**既有前缀之后追加** `build=<git 短哈希> built=<构建时间> target=… profile=… features=…`；**日志首行**同样带 `build=<哈希> <时间>`。同一版本号的任何一次构建从此都能区分（本项目 release 构建不可复现）。⚠️ 解析方请按"**前缀 + 可选追加**"处理（`CONTRACT.md` §2.1） |

## 3. ⚠️ 必须知悉的语义 / 布局 / 流程变化

> 以下每一条都可能让**按旧假设写的调用代码**出错。逐条见 `CONTRACT.md` §4。

### 3.1 语义变化

| 项 | 旧行为 | 新行为 |
| :--- | :--- | :--- |
| **更新失败** | 部分更新（逐文件继续，仅记日志） | **全量回滚**（重试次数由 `--write-retries` 控制） |
| **`--args` 处理** | 分词 + 再加引号（双处理） | **原始片段直拼**，不二次转义（对正确用法等价） |
| **提权后主程序权限** | 继承管理员（High IL） | **默认降权为 Medium**；需保持管理员时加 `--keep-elevation` |
| **等待目标进程超时的退出码** | `1` | **`2`**（此时尚未改动任何文件，"零改动"语义更准确） |
| **版本与降级防护** | 不读版本号，任意包直接覆盖 | 读清单与 state；**更低版本默认拒绝**（退出 2）；包内无清单则跳过并告警 |
| **`.updatekeep` glob 匹配范围** | 匹配完整路径 / 文件名 / **任一中间路径段** | 匹配完整路径 / 文件名（basename）/ **任一上级目录前缀**。规则形如 `sub*` 时不再命中 `a\sub1\b.dll` |

### 3.2 能力新增

| 项 | 说明 |
| :--- | :--- |
| **版本回退** | 保留上一版本 + `_meta.txt`；`--rollback-previous` 还原（回退事务可再回退） |
| **中止后一致性** | 三层自愈（看门狗 + 冷启动 + `--recover`）；**承诺 L1+L2**，冷启动为尽力而为 |
| **target 内自更新** | 支持（影子 Worker），旧版为强制跳过自己 |

### 3.3 布局 / 位置变化

| 项 | 旧 | 新 |
| :--- | :--- | :--- |
| **安装目录常驻** | 临时目录全清理，无常驻残留 | **唯一新增** `<target>\.updater\`（Hidden + System）；稳态只有 `state` 一个常驻文件（+ 可选 `previous\`） |
| **运行时副本位置** | 调用方通常自置于 `%TEMP%` | `%LOCALAPPDATA%\<安装目录名>-updater\<hash8>\runtime\`（回退 `%TEMP%`） |
| **默认日志位置** | `%TEMP%\updater-<ts>.log` | `<base>\logs\updater-<ts>.log` |

### 3.4 流程变化

| 项 | 说明 |
| :--- | :--- |
| **打包要求** | 需额外包含 `updater.manifest`（**可选但强烈建议**；缺失则失去降级防护与逐文件哈希自检） |
| **调用方启动自检** | 若存在 `<target>\.updater\journal`，**建议**同步执行 `updater.exe --recover --target <dir>`（**可选加固，非硬性契约**，见 §1.1） |
| **清理白名单** | 自净逻辑必须把 `.updater\` 加入白名单 |

### 3.5 新增的两条人工恢复路径（2026-09-16）

| 项 | 说明 |
| :--- | :--- |
| **自身修复入口** | `updater.exe` **无参数**（或 `--recover` 省略 `--target`）⇒ 收敛**自身所在目录**。安装目录里双击即可。`--silent` 抑制其失败提示框 |
| **更新包保留** | 调用方在确认更新成功前**不得删除**更新包，且应放在可预期位置；`--delete-zip` 默认关闭。手工解压**不遵守 `.updatekeep`**，仅当包内不含受保护路径时可用 |
| **打包顺序规则** | 启动闭包（根目录直系文件 + `data/*.so`/`data/*.dat`，可由 `.bootclosure` 覆盖）必须**连续排在 zip 末尾**；`scripts/release_pack.ps1` 已实现并带**回读校验**。违反的后果是"掉电后应用可能起不来" |

## 4. 已删除的参数

以下参数在 v4.3 中移除，传入会**按未知参数拒绝并退出 2**（不会静默忽略）：

| 参数 | 原用途 | 移除原因 |
| :--- | :--- | :--- |
| `--splash` | 图片进度窗 | 需 PNG 解码器（依赖预算不允许）与窗口消息循环（与"并发原语 0 个"冲突）；价值与 `--progress-file` 重叠 |
| `--rm-shutdown` | Restart Manager 强制清场 | 会静默关闭用户正在使用的程序，与"绝不伤害用户工作状态"的立场冲突 |
| `--pid-image` | 进程映像名核对参数 | 由 `--launch` 自动派生 |

## 5. 退出码

| 码 | 含义 |
| :-: | :--- |
| `0` | 成功；**或**派生路径的"已交接"（**不代表更新完成**） |
| `1` | 更新失败，已完整回滚 |
| `2` | 中止（预检失败 / 锁占用 / 等待 PID 超时 / UAC 取消），**目录零改动** |
| `3` | 灾难：已提交但拉起失败，或回滚未完成，**需人工介入** |

## 7. 与兄弟项目（lite 版）的差异

参数与单位**完全兼容**，但有 **9 处行为差异**（4 处改变"成功还是失败"、3 处契约变化、2 处语义漂移）。
逐项影响与调用端核对清单见：

- `USAGE.md` §11
- `updater-vs-better-updater-reliability-recheck.md` §2（A/B/C 三类）

**迁移注意**：本版相对 lite 版新增了「运行期目录可用性」「预检严格性」「提交前哈希自检」三道前置门槛 ——
命中即**安全中止**（目录零改动，但更新不发生）。普通使用下最可能的现象是"没更新、回退旧版"，而不是"搞坏目录"。
