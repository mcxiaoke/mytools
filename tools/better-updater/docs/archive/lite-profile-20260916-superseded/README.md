# `--lite` 档位：被否决的实现（2026-09-16）

> **这里的东西不要应用。** 本目录是一份**被撤销**的实现的留档，只用于"将来若需重建"时少走弯路。

## 是什么

2026-09-16 为"吸收兄弟项目 `updater/`（lite 版）的行为、以便删除该项目"，
实现过一个 `--lite` 档位：**只关掉「派生」与「持久化」两类能力**
（不派生影子 Worker / 看门狗、Journal 仅内存、收尾清除 `.updater`），
且 `transaction.rs` / `restore.rs` / `planner::build` / `keep.rs` **零改动**
（满足了 `SCOPE.md` §4.3「禁止第二套实现」）。

同日**实现完成后决定撤销**，撤销理由与完整推理链见
[`../../../CHANGES-20260916.md`](../../../CHANGES-20260916.md) §5。一句话版本：

> 它换走的恰好是 **L2（杀软清理 / `taskkill` 后的收敛）**、版本防护与离线回退，
> 而换来的收益（免白名单、无运行期目录门槛、零残留）**都有更便宜的替代方案**。
> 且它存在的初衷是"避免维护两套"——保留档位本身就是把两套从两个仓库挪进一个二进制。

## 若要重建

`src.patch` 是基于**撤销前那一刻**的 `src/` 生成的，直接 `git apply` 大概率不适用
（此后 `cli.rs` / `main.rs` 因"自身修复入口"又有改动）。正确做法是**照 `profile.rs` 与
`lite_profile.rs` 重新实现**——这两个文件是完整的、自洽的，且记录了当时的判定逻辑与边界条件。

**重建前请先重读上面那条撤销理由**：当时否决它的三个理由都是结构性的，不会因为时间推移而消失。
