## 22:33:54 已解锁会话拖入已混淆文件自动解密原始文件名修复、双钥匙内存自适应嗅探与跨模式兼容（批次 6）

### 1. 根因分析
- **确定性加密主密钥分歧**：在开启「确定性加密」模式下，文件混淆/加密使用的是通过 `V2Crypto.DeriveDeterministicMasterKey(pin)` 派生的确定性主密钥；而 `MainViewModel` 原先仅缓存了通过 `Config.UnwrapMasterKeyWithPin(pin)` 解包的随机主密钥，两者的 MasterKey 不一致，导致使用缓存密钥解密文件元数据必抛出 `AuthenticationTagMismatchException`。
- **Inspect 凭据传递缺失**：`FileObfuscator.Inspect` 原始签名仅接收 `masterKey`，内部调用读取 Footer/Container 时将 `pin` 与 `recoveryCode` 硬编码为 `null`，丢失了利用当前会话 PIN 解密文件自包含 `emkBlob` 的后备恢复能力。
- **元数据刷新凭据门槛过严**：`RefreshLoadedFilesMetadata` 之前检查 `if (_sessionMasterKey == null) return;`，导致在无随机主密钥材料（如仅凭 PIN 或恢复码解锁）时无法触发列表中已混淆文件的元数据刷新。

### 2. 核心与 ViewModel 改造
- **FileObfuscator 双钥匙快速管线与多级智能降级**：
  - `Inspect` 签名扩展为 `Inspect(filePath, masterKey, fallbackMasterKey, pin, recoveryCode, forStructureWorkspace)`。
  - `TryFillMetadata` 实现高敏阶梯解密：
    1. 首选快速路径：尝试首选主密钥 `masterKey`（<0.01ms）；
    2. 备选快速路径：尝试后备已缓存主密钥 `fallbackMasterKey`（<0.01ms），使得混合模式文件或设置开关与加密时相反时完全无感秒解；
    3. 确定性派生后备：若未直接传入密钥且提供了 `pin`，优先尝试 `V2Crypto.DeriveDeterministicMasterKey(pin)`（常量级派生，<0.01ms）；
    4. 自包含容器后备：尝试通过 `pin` 解密文件自包含 `emkBlob` 获取原始主密钥；
    5. 恢复码后备：尝试通过 `recoveryCode` 恢复主密钥。
- **MainViewModel 双主密钥协同与自适应优选**：
  - 新增 `_sessionDeterministicMasterKey`，与 `_sessionMasterKey` 双轨常驻会话内存。
  - `GetSessionMasterKeys()` 返回 `(primary, secondary)`，根据当前 `Config.Deterministic` 动态优选并作为双钥匙管线传入 `Inspect`。
  - `InspectSingleFile` 与 `RefreshLoadedFilesMetadata` 传递完整凭据，无论是拖入文件还是会话解锁，无论历史文件属于哪种加密模式、无论当前设置开关状态，均自适应瞬时解密原始文件名。
- **CLI 嗅探同步增强**：
  - `Program.cs` 的 `TryGetLocalMasterKey` 增加对 `cfg.Deterministic` 的支持；
  - `unhide` 预演及 `scan` 命令在调用 `Inspect` 时同步传递 `pin` 与 `recoveryCode`。

### 3. 测试与验证
- **单元测试**：在 `DeterministicEncryptionTests.cs` 中增加错误主密钥 PIN 后备测试、PIN 直接派生测试、以及跨模式互解测试 `CrossMode_SwitchingDeterministicSetting_DoesNotAffectInspectOrRestore`（涵盖在确定性开关处于相反状态下相互预览嗅探与还原解密），全量 145 项单元测试全部通过。
- **UI QA 验收**：在 `Qa.cs` 中增加 D2 验收用例，验证在已解锁会话下拖入预制确定性混淆文件，`OriginalFileName` 与 `DisplayOriginalFileName` 均自动解密并正确显示，全量 37 项 UI 验收断言全部通过。

## 18:37:17 引入确定性加密模式（同一文件+密码稳定重现输出）、全局确定性配置盐、原文件轻量特征指纹派生（批次 4）

### 1. 确定性加密独立开关与架构支持
- **配置项扩展**：`HideFilesConfig` 增加 `public bool Deterministic { get; set; } = false` 独立开关，默认保持安全的随机模式（保证密码学语义安全），支持通过界面勾选或 CLI 参数开启。
- **CLI 支持**：`CarroCasketCli hide` 与 `encrypt` 命令支持 `--deterministic`（或 `--det`）选项，`PrintHelp()` 同步补充参数说明。
- **GUI 设置项**：`MainWindow.xaml` 设置面板增加「确定性加密（同文件产出一致）」复选框，即时与配置持久化绑定。

### 2. 全局固定配置盐与跨机器/跨实例一致性
- **常量定义**：`CoreConstants` 引入全局固定确定性盐 `DeterministicConfigSalt = "HF2-DET-CFGSALT!"`（16B）。
- **确定性主密钥**：在确定性模式下，由 `PIN` 与固定配置盐经 PBKDF2 派生 `KEK`，再经 HMAC 派生确定性 `MasterKey`，彻底消除不同机器随机初始化 `config.json` 造成的密文差异。

### 3. 轻量原文件特征指纹与抗 Nonce 复用
- **轻量特征提取**：`V2Crypto.ComputeDeterministicSeed(stream, length)` 读取原文件前 64KB（不足 64KB 按实际长度）+ 文件总长度计算 SHA-256 指纹，耗时 < 0.1ms，兼顾结构锁的秒级速度与高雪崩隔离度。
- **材料确定性派生**：`V2Crypto.DeriveDeterministicSaltsAndNonces` 结合主密钥/KEK 与文件指纹派生 `fileSalt`、`fileNonce` 与 `emkNonce`，彻底消除随机源；且只要原文件内容或大小不同，派生 Nonce 必然不同，杜绝 Nonce 复用漏洞。
- **无缝自包含兼容**：结构锁与整体加密容器自包含存储所有解密所需盐与 Nonce，解密端无感兼容解密。

### 4. 测试与验证
- **单元测试全覆盖**：新增 `DeterministicEncryptionTests.cs`，涵盖全文件加密与结构锁的确定性重现验证、跨机器实例一致性验证、文件名混淆下的重现性验证、不同文件 Nonce 隔离性以及解密还原无损验证；全量 141 个单元测试全部通过。
