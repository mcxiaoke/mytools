# Change Log - 2026-11-17

- **2026-11-17 20:14:57**：实施 v2 全加密容器格式（重大重构，不兼容旧格式）：
  1. **新容器规范**：统一 8 字节魔数 `89 48 46 0D 0A 1A 0A 9F`（不泄露源格式），120 字节定长头（版本/模式/标志/configSalt/fileSalt/fileNonce/emkBlob/metaLen）+ TLV 元数据（整体 GCM 加密）+ 模式相关主体。文件自包含可独立搬运。
  2. **密钥体系**：PIN → PBKDF2(60万次) → KEK → 加密主密钥 MK；MK + fileSalt → HKDF → fileKey。恢复码 = MK 的 Base32，可脱离 PIN 解密。config 仅存加密后的 MK，不存明文 PIN/MK。
  3. **双模式**：默认结构锁（新增 `StructureLocator`，纯 BCL 解析 mp4/mkv/jpg/png 关键结构：stco/co64/stsc/stsz/stss/avcC/hvcC、CodecPrivate/Cues/SeekHead、JPEG 参数段、PNG IHDR+IDAT；主体保持明文，CTR 原地加密锁定区）；可选整体加密（64KB 分块 AES-256-GCM，每块独立 tag）。结构锁找不到关键结构时直接报错并提示改用整体加密，不再静默兜底。
  4. **删除 v1**：移除 `MetadataBlock.cs` 与旧"头部 XOR + 明文尾部元数据"协议，不留兼容分支。CLI 新增 `setpin` 命令和 `--pin/--recovery/--mode` 参数；GUI 设置页新增模式切换与一次性恢复码显示。
  5. **实测验证**：用 `F:\Temp\media` 真实 mp4/mkv/jpg/png 端到端闭环（魔数隐藏、无源格式签名泄漏、错误 PIN 拒绝、SHA-256 逐字节一致、ffmpeg 无法直接解码）全部通过；15 项单元测试通过。2GB mkv 实测结构锁混淆 6.1s / 还原 4.7s（大文件为整体读写，10GB 预计还原约 24s）；小文件还原 139–155ms。
  6. **修复实施中的 3 个缺陷**：CTR counter block 须为 16 字节、还原主体长度须用原始长度而非容器全长、MKV Segment 超大尺寸须按缓冲区边界递归定位。

- **2026-11-17 19:12:29**：修复 PIN 保存后不生效、GUI 始终显示"未设置 PIN"、还原不验证 PIN 的严重缺陷（根因）：
  1. **根因**：`HideFilesConfig.Save()` 使用 `JsonStringEnumConverter` 将 `NameObfuscationMode` 以字符串（如 `"HashStem"`）写入 config.json，但 `Load()` 的反序列化选项未注册该 Converter，导致 `JsonException: The JSON value could not be converted to NameMode`，又被 `catch` 静默吞掉并返回 `CreateDefault()`（PinHash=null）。因此每次启动 GUI 都读到默认配置，`HasPin=false`，PIN 状态永远显示未设置、还原门控被绕过。诊断实测：磁盘 config.json 的 PinHash 非空，但 `Load().HasPin=False`。
  2. **修复**：在 `Load()` 的 `JsonSerializerOptions` 中与 `Save()` 对称注册 `JsonStringEnumConverter`，使带字符串枚举的配置文件可被正确反序列化，PIN 等所有持久化字段正常读回。
  3. **回归测试**：新增 `Config_SaveAndLoad_PreservesPinAcrossRestart`（验证 Save/Load 往返后 PinHash 与 PIN 校验均保留、枚举值正确），全量 10 项测试通过。
  4. **重新发布与部署**：重跑 `publish.ps1` 生成 App/CLI 产物与 SHA256，覆盖更新 `C:\Home\Tools\HideFiles` 安装目录（覆盖前已备份至 `temp/backups/install_20261117_191158`）。修复后诊断实测 `Load().HasPin=True` 且 PinHash 正确读回。
